# 姓名、态度连续性与双角色登录修复

- 标准“父亲—外地工作儿子”的新演绎，在接触背景中冻结儿子随父姓的共同事实。已明确随母姓、改姓或特殊亲属关系的画像不补此默认事实；已有亲属全名不被覆盖。其他关系保持原画像设定。
- v16 提示词区分骗子真实画像与冒充身份。真实姓名不能用于冒充者自称或本人材料；已知姓氏冲突属于决定性反证，受害者明确识破并结束联系，解说可按前四轮例外收敛。V42 只新增激活版本，旧提示词及历史快照不重写。
- 首次付款后的暂缓或拒付须承接已知事实并说出具体原因。等待已付检查结果、商量余款或本轮暂不追加，不直接判为停止；已发生的付款与损失始终保留。
- 同浏览器使用一个安全 Cookie，分别保存 USER/ADMIN 认证、CSRF、并发登记。前端标签页使用 sessionStorage 记录身份；认证接口以 X-Login-Role 选择上下文，业务接口按 URL 固定选择，真实权限来自已认证账号。
- 登录仍轮换会话标识，同步迁移并发记录、计时样本和 SSE 关联。分别退出与同账号重登仅影响对应角色；用户退出仍收敛其演绎，管理员退出不影响用户。

验证：后端166项、前端54项测试通过，并通过类型检查、生产构建和 OpenAPI 校验；覆盖两种登录顺序、后台写入、两类退出、跨浏览器重登、计时样本和 SSE 生命周期。用户授权后调用真实模型检查四组虚构样例：冒充材料姓名、已知姓氏冲突、首次小额付款后的理由、暂缓追加的解说判定。

实际模型的姓氏冲突样例最终输出：“你不是我儿子，这钱我不转，以后也别再联系了。”暂缓追加样例说明新增检查费用的顾虑；等待检查结果的解说输出 cooperationStopped=false、candidateOutcome=null。

启用方式：更新并重启后端以应用 V42，刷新前端后在不同标签页分别登录。姓名事实与新提示词针对新演绎生效；已有历史保持原内容。未执行浏览器双标签页端到端检查和实际数据库升级验证；模型样例通过不代表生成结果绝对确定。
