# 骗子报酬资金校验重试修复

日期：2026-10-25。

## 用户现象

场次53刷单返利第6轮依次出现 `fund quote is not a new executed action`、`reward is not a new executed payout`，三次模型调用后前端显示角色对话生成失败。

第一条表示资金quote未通过本轮新执行动作判据，第二条表示REWARD未满足明确完成发放或再次同额发放的要求。这些判据用于防止承诺、查收提醒、既有到账确认重复入账，不能直接删除。日志没有保存供应商失败响应，不能确定本次是否还涉及某种合法自然语言表述被误判。

## 确认的代码缺口与修改

此前只有旁白接入“上次校验失败原因”，骗子仍用不带反馈的Supplier调用重试。虽然日志记录了错误，模型每次实际收到的提示词仍相同。现在骗子同样复用已有带反馈的重试流程，每次收到最近一次失败原因，不增加调用次数或延长超时。

AgentRunner保留旧入口，新增带反馈入口；失败后要求重新输出完整JSON，保持场景与已发生事实。对刷单/投资资金场次强调：

- 未来承诺、操作完才支付、查收提醒及确认旧到账不是新出款，应使用空fundActions。
- 确有本轮新发放时，quote须包含本轮原文、阿拉伯数字金额和明确完成支付/转账/发放的表述。
- 同一笔不能重记；真正另一次同额发放必须明确标识新执行。
- 不得把承诺改写成已付款来凑校验，不得编造行动，不修改金额上限或关联付款约束。

不放宽AgentOutputValidator，不吞掉资金动作、不替模型修改资金结果，不写固定金额或刷单示例进共用提示词。无资金场次与借款场次不追加这组出款说明。未改变已发布模板或迁移、前端提示及历史记录。

此外，重试耗尽或不可重试时保留最终错误原因日志，使用“no further retry”，不再误称还会重试；不打印完整模型响应、提示词或密钥。

## 简单验证

仅运行ScammerRetryTest三项本地检查，3项通过、0失败、0错误：

1. 用模拟响应依次复现两种拒绝，验证最新失败原因传到下一次请求；第三次明确新发放可通过资金校验。
2. 已入账报酬的收款确认先被拒绝，修正为空资金动作后通过，余额和累计报酬不增加。
3. 持续非法发放仍失败；配置0/2次重试分别只调用1/3次，预算不扩大。
