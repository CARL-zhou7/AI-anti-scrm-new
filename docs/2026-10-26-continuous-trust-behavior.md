# 连续信任、自然态度与风险（2026-10-26）

用户明确区分：付款权限可以有硬门槛，谨慎程度不能在同一付款区间保持不变。60 与 70 即使均未达到 75 的小额付款门槛，70 也应更少主动盘问、更愿意接受解释。此要求覆盖旧的按付款档位生成固定态度和固定风险档的设计。

## 行为

AgentContextAssembler 将付款决定与表达控制分开。后台根据每一点信任值生成连续表达强度：主动追问强度为 (1-trust/100)^2，接纳解释倾向为其互补值。60 对应 0.1600/0.8400，70 对应 0.0900/0.9100，71 继续变化。

角色生成器收到的是表达控制要求，没有实际信任分、付款分数阈值或信任加减系数；模板明确这些不是人物所知事实，台词及 psychology 不得报数或复述控制要求。追问弱时减少主动索要照片、单据、回拨和重复确认，已解释部分自然接受，优先关切与帮助。明确反证仍如实处理。

付款预算和 ActionGate/FundRules 继续使用冻结门槛；表达放松不会自动增加付款资格，也不会让拒绝付款变成声称没钱或全面怀疑。

## 风险

正式保存的新 trust-v1 风险为当前信任分（0 至 100 整数），不再按接受/小额/大额门槛跳成 0/25/50/75。已经受骗也不永久锁在 100，当前继续受骗风险可以随信任变化；actualFraudOccurred、goalAchieved、付款流水及历史损失照常保留，不能因降分而撤销。

新风险值来自程序，不由解说模型的辅助五档判断覆盖。旧记录不回填、不重算。前端 RiskNodeBar 显示数值和连续指针，五个节点仅作刻度；颜色与既有 CSS 使用最近的刻度色，复盘折线按保存的真实数值绘制。

V33 仅把 ck_round_risk_score 放宽为 0 至 100；V34 追加 VICTIM 版本 10（v11/victim.txt）。旧迁移与模板不修改。API RiskScore 范围同步为 0 至 100，原有五档记录仍可读取。
