## 1. 文档说明与需求基线

V3.1及后续经确认的修订优先于V3.0、旧构想和旧资料。未在本版保留的能力不得从旧资料自动继承。原13章结构、八个模块和需求编号保留；业务规则、流程、页面状态及验收已按评审结论同步更新。

### 1.4 术语

| 术语 | 产品含义 |
|---|---|
| 诈骗场景 | 定义诈骗类型的基础内容，管理信息为场景名称与简介 |
| 骗子画像／受害者画像 | AI人物角色模型，包含基础信息、行为参数和人物情境 |
| 基础事实 | 受害者跨场景保持一致的真实资料：年龄、职业、家庭、收入、支出、存款、可立即动用资金和预留资金安排等 |
| 场景资料 | 同一受害者在某一诈骗场景下的决策特点与经历；三名初始受害者各有三套，共九组 |
| 一次演绎 | 一个用户使用一个场景、一个骗子画像和一个受害者画像形成的一次体验 |
| 一轮 | 骗子一次发言或行动，加受害者一次回应；解说不另算一轮 |
| 完整轮结束位置 | 双方互动已完成，本轮解说与风险已产生、保存并正常呈现，必要媒体展示已完成的位置 |
| 实时解说 | 每轮受害者回应完成后，对本轮过程提供分析；不等待整场结束才补充分析 |
| 受骗风险指数 | 解说Agent提供的0、25、50、75、100五档教学指标，指向受害者当前受骗风险，不是现实概率 |
| 可动用资金 | 该受害者在本次故事时点可立即使用的资金，来自画像基础事实；预留资金不自动计入 |
| 普通预留 | 画像中可在符合门槛时动用的预留资金，如生活预留、经营周转、长期储蓄；不等于应急资金 |
| 应急预留 | 画像中专门用于家庭应急、养老应急的资金；不论本次金额大小，动用均需较大金额门槛和符合人物背景的理由 |
| 小额行动 | 本次付款金额和本次付款后累计未退回本金都不超过该人物该场景小额上限的资金行动；对应小额门槛 |
| 较大金额行动 | 本次付款金额或本次付款后累计未退回本金任一项超过小额上限的资金行动，以及任何动用应急预留的行动；对应较大金额门槛 |
| 累计未退回本金 | 本场累计实际付款减去累计退回本金；到账报酬不计入本金退回，不能降低该累计值 |
| 报酬 | 骗子以任务奖励、返利等名义实际付出的额外款项，可以与先前付款无关，也可以在本金之外；口头承诺不是报酬到账 |
| 受骗倾向分 | 0—100分，原名“信任分”；表达受害者因相信、压力、紧迫感或人情而让步的综合倾向。骗子和受害者始终看不到分数、阈值、系数和事件明细；观看者在实时逐轮解说三栏卡中可见本轮真实变化量、轮初分→轮末分和趋势，第15轮结束后报告和历史结果仅展示最终分与净损失。不等于五档风险，也不等于现实受骗概率（V1.4／D9） |

## 2. 产品定位与核心价值

### 2.1 产品定位

本产品是面向普通用户的AI反诈教育平台。用户通过观看AI生成的诈骗情景演绎，理解诈骗如何发起、推进，以及受害者为什么相信、配合、怀疑、核实或拒绝。

骗子Agent与受害者Agent承担演绎，解说Agent承担第三方分析。MVP中，用户是观看者和学习者，不直接参与双方聊天。

**角色信息边界：**受害者不知道自己正处于诈骗演绎中，也不预先知道联系者是骗子、当前诉求是假的。受害者只能依据自身基础事实、场景经历和实际交流判断：

- 不能因为场景名称包含“诈骗”就提前识破。
- 不能因为自己被设为高风险或低风险人物而直接给出结果。
- 不要求每轮主动提醒风险、质疑身份或重复核实。
- 可以依据具体证据怀疑、核实、配合或停止。

解说和观看者可以了解教学分析；解说结论、风险分和内部心理不自动成为受害者已知事实。对应第9章AGT-02、第11.3节和FR-SIM、PC-P02。

### 2.2 用户价值

| 用户需要理解的问题 | 产品提供的学习价值 | 对应能力 |
|---|---|---|
| 诈骗如何一步步发生 | 通过连续对话和行为看见过程，而不仅看到案例结论 | AI情景演绎 |
| 话术为何会产生影响 | 识别话术、诈骗手段与受害者心理之间的关系 | 实时解说 |
| 什么行为可能改变风险 | 结合人物反应与风险变化理解关键节点 | 风险指数、解说 |
| 演绎结束后应该记住什么 | 回顾关键话术、行为和结果，整理防范启示 | 分析复盘 |
| 如何重新查看学习内容 | 查看本人的演绎过程与报告 | 历史记录 |

这些是产品的教育目标，不构成对用户个人能力的量化测评结论。当前不设置用户反诈能力评分或雷达图。

### 2.3 管理员价值

管理员维护基础场景和双方画像，使普通用户能够选择并体验基础内容。管理员职责不包含查看、分析或运营用户个人演绎与复盘数据。

## 3. 产品核心体验说明

### 3.1 完整体验

核心体验为：**选择配置 → 进入人物与情境 → 观看双方演绎 → 同步理解解说与风险 → 复盘学习 → 历史回顾**。

用户主要关注角色互动，解说和风险帮助其理解情节。每次正常演绎固定15轮，第15轮结束后按最终受骗倾向分与实际净损失判定骗子胜或受害者胜；不因分值、付款、反证、资金不足或场景关键目标达成提前结束，也不设600秒业务上限。正常体验应通过每轮推进和第13至15轮的收束形成完整故事，不能以频繁技术中断代替完整演绎。复盘生成与阅读不改变轮次或胜负。

### 3.2 沉浸式诈骗情景演绎

- 演绎页先加载场景介绍动画与双方立绘资源，就绪后显示“开始演绎”；点击后依次播放场景介绍动画（含本次场景名称与简介）和双方人物卡（形象、姓名、性别、年龄、身份），再进入正式演绎。
- 舞台左侧为骗子、右侧为受害者，位置全程固定；角色为半身立绘，具有待机浮动和说话时的嘴部开合与轻微身体动作，当前发言角色突出，非发言角色保持待机。
- 双方各有独立对话气泡；同一轮内双方气泡保留至本轮解说停留结束，下一轮开始时仅清理前端舞台气泡，不影响已保存的历史对话。
- 按骗子、受害者的发言顺序呈现：角色进入说话状态→气泡出现→台词随语音进度逐步显示→语音结束恢复待机；两方语音不重叠，声音可区分且同场固定，文字与播报内容一致。角色的模拟行动以动作说明展示，不朗读。
- 人物表现遵循所选画像，情节遵循所选诈骗类型；年龄侧重不改写用户所选人物。
- 受害者按所选场景资料表现信任、怀疑、配合、核实、拒绝或停止，但不知道自己处于演绎中；不得直接使用场景名称、风险标签、解说结论或未来剧情作为判断依据。
- 顶部只保留设置按钮；打开设置即暂停演出，可开关声音、继续演绎或退出演绎（BR-P13）。静音不影响文字、动画、解说和评分，不属于媒体故障。

本期采用基础人物动画（待机浮动、嘴部开合与轻微身体动作）；情绪表情与复杂动作增强属于未来方向。具体媒体标准集中见第12.2节、PC-P04、PC-P06及第14章。对应FR-SIM-01至FR-SIM-04、FR-SIM-08、AGT-01、AGT-02、UX-01、UX-06。

### 3.3 多Agent协同

| 参与者 | 在体验中的作用 |
|---|---|
| 骗子Agent | 通过符合场景和画像的行为、话术推进诈骗情节；只使用公开或本次交流已披露的资料，不读取解说结论、内部心理、受骗倾向参数、余额与预留划分或未来内容；使用开始时的场景规则快照 |
| 受害者Agent | 依据基础事实、当前场景资料、实际收到的对话和材料表现心理变化与行为反应，影响后续互动；不知道自己处于演绎中，不知道后续剧情、内部评分或行动阈值；每轮回应，可以持续拒绝或核实 |
| 解说Agent | 分析当前过程，按统一规则给出风险依据；在完整一轮结束后识别受骗倾向事件与反证并提供原文依据，由程序结算；解释最终胜负，不另判 |
| 普通用户 | 选择配置、观看学习、控制声音、查看本人复盘及记录 |

双方演绎、解说和风险围绕同一次体验形成对应关系。同一次演绎只保留一个胜负，复盘和历史共同引用。协作是产品职责与可见效果，不规定技术组织或调用方式。

### 3.4 实时解说与动态风险感知

每轮受害者回应完成后，解说呈现诈骗阶段、骗子话术、诈骗手段和受害者心理，并提供风险分值及简短依据。实时主卡采用三栏结构：左栏是本轮“骗子的手段”短标签（`methodShort`），中栏是一句“骗子想做什么？”意图说明（`intentShort`），右栏是真实受骗倾向分变化（变化量、轮初分→轮末分及趋势，对应`trustChange`）；五档风险节点条作为独立辅助区，不与受骗倾向分合并。短标签和意图句单独保存，只供实时解说；完整的话术与手段分析（`speechAnalysis`/`methodAnalysis`）仍保存，并供复盘报告和历史详情读取。解说与角色发言清晰区分，不提前呈现下一轮内容。下一轮演出期间，解说区继续显示上一轮解说与风险并标注所属轮次，直至被新一轮内容替换。

开场风险显示“尚未评分”；首轮完成后开始展示分值。风险只使用0、25、50、75、100，不累计加减。完整口径见第10.2节。用户可以将每次变化与对应行为联系起来；分数不是观看用户的能力，也不直接决定正式结果。后台另有受骗倾向分用于付款门槛和最终胜负判断；按D9，观看者在逐轮解说三栏卡中看到本轮真实变化量和前后分，但看不到阈值、系数、事件明细或角色内部提示，五档风险仍独立展示（BR-P15）。

实时解说贯穿逐轮演绎，不能在整场结束后才统一补充。对应FR-SIM-05、FR-SIM-06、AGT-03、AGT-04。

### 3.5 复盘学习

第15轮完成后生成简洁复盘：一句话胜负结果及依据（骗子胜或受害者胜、最终分值、实际净损失）、按“接触背景→诈骗推进→关键判断→最终结果”组织的过程总结、最多3个关键节点、2—3条对应本次问题的防范建议，并保留实际风险变化折线图。默认约400—600字，取消逐轮必分析和重复长篇栏目。报告引用实际内容、过程事实和唯一胜负结果，不预设一定上当，不重新评分，也不把画像表现当作观看者能力；过程曾经付款、后来追回，仍照实呈现。

已完成报告可从历史再次查看；报告失败允许基于原演绎手动重试，旧失败报告使用当时规则。技术故障中断只保留过程，不生成正式报告；观看用户主动退出属于正常业务结束，生成如实报告并写明“未形成胜负结论”。历史不提供音视频回放。对应FR-REV-01至FR-REV-05、FR-HIS-01至FR-HIS-03。

## 6. 核心业务流程

### 6.1 普通用户主流程

**注册后登录／直接登录 → 首页 → 场景选择 → 双方画像选择 → AI情景演绎（完整15轮）→ 第15轮结束后判定胜负并分析复盘 → 历史记录。** 正常完成15轮属于正式结束，产生骗子胜或受害者胜；观看用户主动退出属于正常业务结束，不判胜负并生成如实报告；技术故障中断保留已保存内容供历史查看，不进入正式报告生成。管理员另有“演示测试模式”，在同一演绎页观看本人测试场次并使用魔法球当场干预。

| 节点 | 进入条件与目标 | 用户操作与反馈 | 使用或产生的信息 | 去向与规则 |
|---|---|---|---|---|
| 注册／登录 | 获得普通用户身份 | 提交用户名、密码等规定信息，获得校验反馈 | 账号与身份状态 | 注册成功回登录页，登录成功入首页；BR-P11 |

画像选择不要求拆成两个物理页面。无效配置或画像已停用时提示修正；同一账号已有演绎进行中时阻止新建，不替换既有演绎。演绎页的资源加载发生在点击“开始演绎”之前；开始时若当时配置的立绘与预加载资源不一致，补充加载后继续。管理员演示测试场次与普通用户场次一样受单场活动限制，但只能由本人访问。

### 6.2 演绎内部流程

1. 用户在演绎页资源加载完成后点击“开始演绎”，使用本次确定的场景和画像内容依次展示场景介绍动画和双方人物卡；风险显示“尚未评分”。开场期间系统可在后台预先准备第1轮骗子草稿，但不提前展示。本版不设600秒业务时限，开始后的等待、解说和阅读停留按正常流程推进，不会因时长到达而提前判胜负。
2. 系统生成骗子草稿。普通用户场次按既有规则直接采用；管理员演示测试场次先进入“待确认”状态：舞台展示本轮草稿，管理员可点击“继续”采用原稿，或打开魔法球输入指导重新生成、直接修改台词，反复调整后确认最终版本。只有最终采用的版本才保存为正式骗子消息并触发资金动作；“未确认”“已重新生成但未采用”的版本不保存为正式消息，不影响受害者回应、受骗倾向计分和资金状态。规则见BR-P18。
3. 正式骗子消息保存并呈现后，系统生成受害者回应；受害者回应及其付款、预留释放随消息一并保存。受害者可以拒绝、质疑、核实或只表达付款意向；是否实际付款由程序按上一轮已结算的受骗倾向分、金额、用途、疑点和资金能力校验，不能先付款再补分。骗子内容呈现期间可预备受害者回应；受害者回应呈现期间可预备本轮解说及下一轮骗子草稿；预备内容在轮到呈现前不保存、不展示，本轮结束或中断时直接丢弃。
4. 双方回应完成后，解说Agent依据“完整一轮”的实际效果分析本轮，给出风险、依据、资金事实，并识别受骗倾向事件及反证；程序在同一轮结算中按事件基础分×人物系数计分，处理反证降分与反证成立状态。本轮结算的新分值从下一轮起影响对话、行动与付款资格；本轮已发生的付款仍以本轮开始时已保存的分值为准。骗子和受害者看不到事件与分数；观看者只在已保存分析发布后看到程序投影的真实变化量和前后分，事件明细不展示。
5. 本轮解说、风险和资金流水保存成功后展示。检查轮号：未满15轮时，阅读停留后进入下一轮；第15轮完成并结算胜负后，保存唯一胜负结果并触发复盘。第1至14轮不因分值达到80、发生付款、出现反证、达到场景关键目标或资金不足而提前结束。
6. 第15轮结束时按第10.4节判定：最终受骗倾向分≥80或实际净损失＞0为骗子胜；最终受骗倾向分＜80且实际净损失＝0为受害者胜。最终分值取第15轮结算后的分值；曾经达到80、曾经付款或中途识破都不单独锁定胜负，过程事实照实保留。
7. 若第15轮完成前发生生成、语音、动画或保存故障，立即停止推进，保留已保存内容和实际状态，按技术故障中断处理，不生成正式报告。观看用户主动退出属于正常业务结束，保留过程并生成如实报告，写明“未形成胜负结论”。
8. 用户打开设置界面时演出暂停；继续后从暂停位置恢复，不重新开始本轮、不重复已完成的台词。本版暂停不再按累计时长顺延任何业务截止时间（BR-P13）。
9. 管理员演示测试场次的魔法球同时提供“当场干预”和“待入库记录”两个区域；已采用干预可在测试几次后集中归纳为场景规则并提交知识库。规则只影响之后新开的同场景场次，进行中的场次沿用开始时的规则快照（BR-P18、BR-P19）。

| 情况 | 处理与去向 |
|---|---|
| 第1至14轮出现分值达到80、付款、反证或关键目标达成 | 继续演绎，不提前结束，不提前宣告胜负；保留已发生的过程事实 |
| 第1至14轮受害者持续拒绝、坚持核实或不付款 | 继续演绎；允许该轮分值和资金都不变化，不强迫重新相信或付款 |
| 第15轮完整结束 | 结算本轮受骗倾向分与净损失，按第10.4节判定骗子胜或受害者胜，生成复盘 |
| 第15轮完成时受害者仍有未完成的核实或材料 | 最后一轮必须形成最终态度与资金结果，不把“等待材料／等待回应”当作收束；按第10.11节复核 |
| 管理员演示测试场次中骗子草稿待确认 | 受害者不生成、不计分、不付款；只有“继续”或确认修改后的最终版本才生效 |
| 管理员魔法球中重新生成或直接修改台词 | 仅替换本轮草稿；可以改变表达、策略和请求，不能凭空创造到账、退款等实际资金事实 |
| 管理员确认最终台词 | 保存正式骗子消息并呈现，随后按正常顺序生成受害者回应 |
| 管理员未确认即离开、刷新或中断 | 草稿不生效；按主动退出或技术故障对应规则收敛，不补造受害者回应 |
| 正式结束前观看用户主动退出、刷新、关闭页面 | 正常业务结束，保留已保存内容并生成如实报告，写明观看用户主动退出、未形成胜负结论 |
| 关键内容、媒体或保存失败 | 技术故障中断，保留已保存内容，不生成正式报告，不提供报告重试 |
| 第15轮完成后观看者离开或报告失败 | 不回退为中断；报告按自身状态处理 |
| 管理员提交场景规则 | 只影响之后新开的同场景场次；进行中场次和已保存历史不变 |

胜负、过程事实、正常业务结束、技术故障中断和报告状态分别表达。正文中的“已结束”只有在15轮完成且胜负保存成功后成立；角色已经说出某个行为，不等于整场已经正式结束。未形成胜负时，报告如实说明结束原因和实际资金情况，不补写骗子胜或受害者胜。

### 6.3 管理员流程

**管理员登录 → 管理后台 → 场景管理／骗子画像管理／受害者画像管理／受骗倾向机制／场景知识库；需要体验和当场干预时，从演绎页进入本人“演示测试模式”。** 五类后台管理入口独立进入，演示测试模式与后台维护分开。

场景仅编辑固定三项的名称、简介。画像支持新增、编辑、停用与重新启用，双方各至少保留一个可用画像。头像由管理员上传符合要求的静态图片。受骗倾向机制维护40／70／85三个阈值和只读的计分规则说明，不提供按场次的分数查看。场景知识库按场景查看、编辑、启用／停用已提交规则；待入库记录只来自管理员本人演示测试场次的已采用干预。演示测试模式复用演绎页，只创建和观看本人测试场次，不能访问普通用户记录。操作结果反馈不改变已完成场次和历史内容。具体规则见第8.8节和第15章。

## 8. 功能模块详细需求

### 8.1 登录注册模块

**模块目标：** 提供普通用户注册及双方共用登录，使账号进入其既定角色的功能范围。

**用户需求：** 新用户能注册并登录；已有用户和预先开通的管理员能登录对应入口。

**功能描述：** 适用于普通用户、管理员；范围MVP，规则已确认。

| 编号 | 功能要求 | 规则依赖 | 验收 |
|---|---|---|---|
| FR-AUTH-01 | 提供普通用户注册，提交有效信息后创建普通用户账号并返回登录页 | BR-P11 | AC-01 |
| FR-AUTH-02 | 用户与管理员共用用户名和密码登录页，反馈成功或失败 | BR-P11 | AC-02 |
| FR-AUTH-03 | 成功登录后按账号既定角色进入用户首页或管理后台 | PER-03、BR-P11 | AC-02 |

账号规则（BR-P11）：

| 项目 | 已确认规则 |
|---|---|
| 注册输入 | 用户名、密码、确认密码；两次密码须一致 |
| 登录输入 | 用户名、密码 |
| 用户名 | 2—24个字符，允许中文汉字、英文字母、数字、下划线；去除首尾空格后校验 |
| 唯一性 | 普通用户和管理员之间全局唯一；英文字母不区分大小写 |
| 密码 | 6—24个字符，允许空格；不自动删除首尾空格，按原样匹配；不强制字符组合 |
| 弱密码 | 允许常见弱密码，包括123456；不设置密码复杂度或常见弱密码拦截规则 |
| 注册反馈 | 成功后回登录页，不自动登录；重复用户名提示“用户名已被使用”；字段不符合规则时说明对应问题 |
| 登录失败 | 统一提示“账号或密码错误”，不分开暴露账号存在与否 |
| 角色 | 一个账号只有一个既定角色；普通注册不能选择管理员 |
| 管理员来源 | 预先开通管理员账号，不建设管理员自助注册或用户管理模块 |

**用户操作流程：** 新用户进入注册，完成字段校验后注册成功，返回登录页并登录；已有用户、管理员直接登录。用户成功进入首页，管理员成功进入后台。

**页面需求：** 注册、共用登录、相互导航、提交和校验反馈。注册页不出现角色选择。

**输入输出：** 输入为上述账号信息；输出为校验结果、账号创建或登录结果、对应角色入口。

**MVP边界：** 不增加短信、邮箱验证、密码找回、角色切换或用户管理。允许弱密码是用户明确确认的基线限制，相关风险见第12.2节，不由技术文档擅自修改。

**用户需求：** 理解场景和画像内容，自主选择一个场景、一个骗子画像和一个受害者画像；理解同一人物在不同场景下的差异。

**功能描述：** 适用于普通用户；范围MVP，已确认。

| 编号 | 功能要求 | 内容／规则依赖 | 验收 |

**输入输出：** 输入为可用基础内容及用户选择；输出为本次场景与双方画像的完整组合，作为演绎与历史的当时配置；受害者配置包含基础事实和三套场景资料快照（本场使用当前场景）。

**MVP边界：** 场景固定三个；初始画像为两个骗子、三个受害者，可由管理员扩充。新增受害者必须补齐三个场景的资料和该场景的受骗倾向参数、金额边界才能启用；用户不创建、投稿或修改行为参数，不单独选择环境，也不在演绎中更换角色。

| 编号 | 功能要求 | 内容／规则依赖 | 验收 |

**页面需求：** 加载等待、开始按钮、场景介绍、人物卡、左右立绘舞台、双方气泡及动作说明、底部三栏文字解说（短手段标签、短意图句、真实受骗倾向变化）与独立五档风险节点条、顶部设置按钮与设置界面、过程状态（详见第14章）。管理员演示测试场次另显示待确认提示、“继续”按钮、魔法球入口、当轮草稿与待入库记录入口（详见第15章）。未生成内容显示等待状态；不能用默认分值或虚构结果占位。资金变化通过动作说明和复盘体现，演绎页不新增独立资金面板，也不展示行动阈值、等待事项状态或内部事件计数。

**输入输出：** 输入为当时配置、规则快照及本次上下文；输出为实际对话、解说、逐轮风险与依据、受骗倾向事件与分数变化（仅后台）、资金流水摘要、胜负与过程事实、正常业务结束原因、技术故障中断原因。保存成功的内容供报告和历史使用。

**MVP边界：** 普通用户不参与双方聊天；提供演绎进行中的设置暂停与继续，不提供中断后续演、倍速或回放。语音、动画故障中断本次体验，不静默降级为完整成功的纯文字演绎。关闭声音属于正常操作，不视为语音故障。不得超出现场可用资金和付款门槛支付，不得为推进剧情凭空补钱或临时增加额度；不得为了推进而降低门槛或改写分数。普通用户在本期不能使用魔法球；管理员只在本人演示测试场次使用。

### 8.5 分析复盘模块

**模块目标：** 将完成15轮或主动退出的演绎整理为简洁、可回顾的反诈学习内容，突出胜负依据、关键过程、最终分值和实际经济影响。

**用户需求：** 快速理解谁胜谁负、为什么，回顾风险变化，知道自己或该人物实际损失了什么，并能够恢复失败的报告生成。

**功能描述：** 适用于普通用户及管理员本人演示测试场次；范围MVP，已确认。

| 编号 | 功能要求 | 内容／规则依赖 | 验收 |
|---|---|---|---|
| FR-REV-01 | 生成一句话胜负结果及依据（最终受骗倾向分、实际净损失、是否曾付款或追回），并按“接触背景→诈骗推进→关键判断→最终结果”组织过程总结 | DATA-03、DATA-04、BR-P04、BR-P17 | AC-17、AC-42 |
| FR-REV-02 | 最多列出3个关键节点，每个节点引用实际轮次或简短原话，说明其作用 | BR-P02、BR-P04 | AC-17 |
| FR-REV-03 | 给出2—3条对应本次问题的防范建议；解释真实信息、虚假主张、危险要求、受害者反应和关键转折，不把所有结果都写成上当原因 | BR-P03、BR-P04 | AC-17、AC-18 |
| FR-REV-04 | 以折线图展示本次实际风险序列，与演绎一致，不另行评分 | BR-C01至BR-C03、BR-P01 | AC-19 |
| FR-REV-05 | 保存报告并关联本人演绎，支持历史查看及生成失败后的手动重试；旧失败报告使用当时规则 | PER-01、BR-P07、BR-P08、DATA-04 | AC-20、AP-06 |

报告规则（BR-P07）：

- 完成15轮的正式结束，以及满足完整轮门槛的观看用户主动退出（正常业务结束），触发报告生成；技术故障中断（对话、解说、语音、动画、保存失败，服务重启，失联）不生成正式报告。用户离开页面不取消生成。
- 主动退出（刷新、关闭、离开页面）只有在服务端确认至少一个完整轮时才生成报告；完整轮指双方正式台词与动作说明、本轮分析与风险、必要呈现回执、本轮计分和实际资金动作均已保存。只有开场、未确认草稿或没有完整轮的半轮结束不生成报告、不开放报告重试，明确提示“未形成可复盘内容”；已有完整轮后在后续半轮退出仍生成如实报告，保留未完成内容，但不判胜负、不展示最终分。
- 报告默认约400—600字，校验允许约300—800字；不机械截断，超过上限才判失败。取消逐轮必分析、重复长篇栏目和逐轮分析数组。
- 报告按“接触背景→诈骗推进→关键判断→最终结果”组织，不补造阶段、不凑节点；重点解释真实信息、虚假主张、危险要求、受害者反应和关键转折。
- 报告必须写明：最终受骗倾向分、胜负、实际净损失、结束时可用资金与普通预留、应急预留的剩余情况，以及对该人物生活、经营、养老或应急能力的具体影响。受骗倾向分、净损失和胜负由程序计算，AI只负责解释，不得虚构贫困、负债或其他没有依据的后果。
- 骗子胜与过程“曾经付款”分别表达；受害者胜与过程“曾经付款、后来追回”分别表达。不得把“过程中曾付款”写成骗子必然获胜，也不得因受害者胜就删除已发生的付款、识破或资金流水。
- 没有形成胜负（主动退出）时，报告如实说明结束原因和实际资金情况，不得强行写成骗子胜或受害者胜；旧记录中的“已受骗／已识破／超限结束”按当时规则展示，不改写成新胜负名称。
- 报告区分“生成中、已完成、生成失败”。未成功生成并保存的报告不能显示为已完成。
- 失败时保留已结束演绎和完整过程。用户可从报告页或历史点击重新生成，仍基于同一次演绎，不重新运行角色互动；旧失败报告使用当时绑定的Prompt、规则版本和报告结构。
- 同一次演绎同时只进行一次报告生成。成功报告保持不变，不提供反复改写入口；本期不要求自动重试。
- 保留实际风险曲线，不重新评分或改判结果。内部心理可辅助分析，但不能证明动作已经完成，也不直接暴露内部备注；过程分、阈值和事件计分不进入报告正文。报告过程总结继续使用完整的话术与手段分析，不使用实时解说的短标签或短意图句替代。报告结果区仅展示最终受骗倾向分、净损失和胜负，用于解释判定依据。

| 结束方式 | 报告必须体现的重点 |
|---|---|
| 骗子胜（最终分值≥80，或实际净损失＞0） | 最终分值、净损失；是分值导致、损失导致还是两者同时成立；过程是否曾付款、是否曾识破、是否曾追回；不把“骗子胜”等同于一定发生付款 |
| 受害者胜（最终分值＜80且实际净损失＝0） | 最终分值、净损失为0；过程是否曾付款后追回、是否识破或始终坚持核实；不因获胜而删除曾发生的风险行为 |
| 无胜负（观看用户主动退出，未完成15轮） | 结束原因、已发生的付款与到账、实际净损失、三类资金剩余情况；明确写出“未形成胜负结论”，不补写结局 |
| 旧记录（V3.4及更早） | 按当时规则显示“已受骗／已识破／超限结束／未受骗结束／结局未定”等旧名称和旧资金口径，不批量改写 |

**用户操作流程：** 第15轮结束或主动退出后查看生成状态，成功后查看报告；失败可手动重试；之后从历史再次查看。技术故障中断不进入报告生成。

**页面需求：** 一句话胜负结果、过程总结、最多3个关键节点、2—3条防范建议、风险折线、最终分值与净损失、资金与三类预留的结束情况、报告状态和失败重试入口；复盘保留一条按轮色条带（每轮一个色块和轮号，不显示分值），关键节点也使用对应轮次的风险颜色边条，已评分轮次不显示分值或文字标牌。资金事实只在报告中简洁呈现，不必平铺全部会计字段。

**输入输出：** 输入为该次已保存对话、解说、风险、资金事实、最终受骗倾向分及唯一胜负结果或结束原因；输出为对应报告。不得补造未发生行为或重新判定成与演绎矛盾的结果。

**MVP边界：** 不包含任何雷达图，不评估观看用户的个人能力；技术故障中断记录不生成报告，也不提供报告重试；未完成15轮但属于正常业务结束时，报告只如实说明，不包装成骗子胜或受害者胜。报告生成失败不把已结束演绎回退为中断。旧成功报告按原结构展示，不批量重写。

### 10.2 风险评分与轮次口径

BR-P01采用五个固定代表分，不设额外权重、区间插值或累计加减规则。开场为“尚未评分”，不是0分。

| 分值 | 本轮结束时的受害者状态 |
|---|---|
| 0 | 已明确拒绝并停止配合，或完成独立核实后终止当前诈骗互动 |
| 25 | 仍在接触但保持警惕、尚未建立信任，或暂停配合并进行核实 |
| 50 | 已表现出信任或考虑配合，尚未承诺、准备或执行危险操作 |
| 75 | 已承诺或正在准备危险操作，尚未实际执行，也未完成有效核实 |
| 100 | 正在执行危险操作，或已经执行且仍继续配合 |

统一判断规则：

1. 每轮结合既有事实和本轮结束状态重新定档，不按上一轮分值累加或平滑。
2. 实际行为优先于口头态度。口头声称警惕但仍执行危险操作，不能仅据该表态降分。
3. 骗子提出转账、验证码等危险要求，不等于受害者已配合。明确拒绝者不能仅因出现危险词语升分。
4. 有效核实、明确拒绝或停止配合会影响当前档位，但不会删除此前受骗行为。已转款后明确停止，可以降为0，报告仍保留转款事实。
5. 每轮提供简短依据，说明当前危险要求、受害者反应和防范行为；无相应行为时不得虚构。
6. 0和100都是教学档位，不表示现实中的绝对安全或100%受骗概率，也不是结束触发阈值，更不直接决定胜负。
7. 资金余额、净损失、到账报酬和追加次数不作为风险分，也不替代风险依据；风险分只表达受害者当前受骗风险，受骗倾向分只用于付款门槛和最终胜负判断，两者都不对外展示为现实概率。

BR-P02的一轮为“骗子一次发言或行动＋受害者一次回应”，解说不另计轮次。回应完成后提供本轮解说、风险与依据；未完成轮不得补造风险。相应内容保存成功后呈现，再按媒体和阅读规则继续。完整轮结束位置还要求本轮解说、风险及必要媒体均正常呈现，供轮次推进和胜负确认使用。

风险分与受骗倾向分是两套独立规则：风险分由解说逐轮重新定档并展示给观看者，用于教学；受骗倾向分由程序在完整一轮结束后按事件结算，观看者在实时三栏解说中看到真实变化量和前后分，但看不到事件明细，骗子与受害者始终不可见；第15轮结束后报告和历史结果仅展示最终分与净损失。两者不互相换算，也不互相替代：风险低不等于受骗倾向低，受骗倾向高也不代表可以无条件付款。

| 场景 | 深度卷入参考（不触发结束） |
|---|---|
| 刷单返利诈骗 | 首次垫付后至少追加1次，且“追加累计3次”或“累计实际净损失达到1000元”之一成立 |
| 虚假投资诈骗 | 已投入投资款后，又实际支付一次所谓提现、解冻等额外费用 |
| 冒充亲友借款诈骗 | 未通过独立渠道核实身份，就实际完成借款转账 |

刷单参考口径：

- 首笔垫付不计入追加次数；后续每笔实际追加投入计1次。
- 实际净损失＝累计实际付款－累计退回本金－累计到账报酬；结果不大于0时视为尚无净损失。退回本金与到账报酬分别记录，报酬不能当作本金退回。
- 首笔即净损失1000元、没有追加的，不构成“追加累计3次或净损失达到1000元”的深度卷入参考，但仍是重要过程事实。
- 按本轮全部已完成行为后的资金情况计算；同轮先付款后到账，按本轮结束时的净额计算。
- 承诺、平台余额、未兑现收益不算实际到账；重复提及或重复记录不能重复计数。
- 上述参考值不形成正式结果，不提前结束，也不改变第15轮的胜负判定。

**最终胜负（BR-P17，V3.5新增）：**

| 第15轮结束时的最终状态 | 胜方 |
|---|---|
| 最终受骗倾向分≥80，无论是否付款、是否存在损失 | 骗子胜 |
| 最终受骗倾向分＜80，但实际净损失＞0 | 骗子胜 |
| 最终受骗倾向分＜80，且实际净损失＝0（包括受害者获得净收益） | 受害者胜 |

可以概括为：

- **骗子胜：最终受骗倾向分≥80，或实际净损失＞0。**
- **受害者胜：最终受骗倾向分＜80，且实际净损失＝0。**

判据与过程事实：

- 最终分值取第15轮结算后的受骗倾向分；第15轮结束后不再产生新的角色对话或改分。
- 曾经在第1至14轮达到80分，不锁定骗子胜；后续质疑、反证、信任回落可以改变最终分值。
- 曾经付款或曾经达到深度卷入参考，不永久锁定骗子胜；后续退回本金、到账报酬或净损失归零，仍可能形成受害者胜。
- 曾经识破、拒绝或停止配合，不单独锁定受害者胜；最终分值仍≥80时，骗子胜。
- 胜负与过程同时保留：受害者胜但过程中曾付款、后来追回，报告仍如实呈现付款、退回本金、到账报酬和净损失；骗子胜但未发生付款时，报告不得虚构损失。
- 实际净损失＝max（0，累计实际付款－累计退回本金－累计到账报酬）；净损失为0不代表没有发生过风险行为。
- 胜负由程序按最终分值与资金流水判定并只保存一份；解说Agent只解释，不另判或改写胜负。

**结束与中断分界（BR-P04，V3.5修订）：**

| 情况 | 结果与去向 |
|---|---|
| 完成全部15轮 | 正式结束，按BR-P17判定骗子胜或受害者胜，生成复盘 |
| 第15轮中仍有未完成必要呈现或技术故障 | 技术故障中断，不判胜负，不生成正式报告 |
| 第15轮完成前观看用户主动退出 | 正常业务结束，不判胜负，保留过程并生成如实报告，写明“未形成胜负结论” |
| 第15轮完成前生成、语音、动画或保存故障 | 技术故障中断，保留已保存内容，不生成正式报告 |
| 资金不足或角色不愿继续付款 | 不结束演绎；受害者可以在剩余轮次继续拒绝、核实或只表达意向，按第15轮收束 |
| 达到场景关键目标参考值 | 不结束演绎，继续完成剩余轮次，结果按BR-P17判定 |
| 第1至14轮出现分值达到80、付款或反证 | 不提前结束、不提前宣告胜负，继续演绎并允许后续变化 |

- 正式结束确认时点：第15轮双方对话、解说、风险、必要媒体、最终受骗倾向分和资金流水均已保存并正常呈现，胜负结果保存成功，才确认正式结束。此后触发复盘生成。
- 确认前发生退出或技术故障，按对应路径处理；确认后最后阅读停留期间离开或后续报告失败，不将已结束记录回退为中断。
- 技术故障中断、正常业务结束和正式结束分别表达；新会话的正式结果只有骗子胜、受害者胜两类。
- “已受骗”“已识破”“超限结束”在V3.4及更早记录中仍是正式结果；新会话不再产生，但“过程中曾付款”“过程中曾识破”仍作为过程事实保留。
- 旧记录按当时规则和当时结果名称展示，不批量改写为新胜负名称。

**最后一轮收束（V3.5新增）：** 第13至15轮应回应当前遗留问题、形成最终行动和态度，并交代资金结果；不得在第15轮结束时停在“等待材料”“等待回应”“准备核实”等中间状态。若受害者仍拒绝付款，最终态度和拒绝理由应明确；若骗子仍在编造新理由，必须与前文事实一致，不能靠重复旧说法填充轮次。

### 10.4 固定15轮与故事节奏（BR-P05，V3.5修订）

BR-P05规定每次正常演绎**固定15轮**。一轮为骗子一次发言或行动加受害者一次回应，共30次角色发言；解说、干预审阅和设置暂停不另计一轮。用户不可调整轮数；三个场景使用相同规则。

| 项目 | 已确认规则 |
|---|---|
| 轮次数量 | 固定15轮；完成第15轮才形成胜负，不生成第16轮 |
| 轮次结构 | 每轮必须有骗子发言／行动和受害者回应；允许某轮分值和资金都不变化 |
| 不提前结束 | 第1至14轮的分值达到80、付款、反证、资金不足、角色拒绝或场景关键目标达成均不结束演绎 |
| 受害者义务 | 每轮必须回应；可以持续拒绝、坚持核实、只表达付款意向或明确不再付款，但不得以“结束对话”代替回应，也不为凑轮数被强迫重新相信或付款 |
| 阅读停留 | 每轮语音、解说和风险完整展示后停留5秒，再进入下一轮或复盘；不再因总时长不足而缩短 |
| 时间限制 | 取消600秒有效时长业务上限；只保留单步生成、语音合成、保存和媒体播放的技术超时。技术超时按中断处理，不判胜负 |
| 最后一轮 | 第15轮必须形成最终行动、最终态度和资金结果，不停在等待材料或等待回应 |
| 节奏要求 | 每轮应有实际推进；连续重复同一说法、同一问题或没有新进展的轮次应被视为质量缺陷并修正 |
| 旧记录 | V3.4及更早的5至20轮、600秒、超限结束和提前终止按当时规则展示，不套用本版轮次规则 |

**15轮参考节奏（PC-P11，V3.5新增）：** 以下只作为内容与验证参考，不强制绑定具体剧情。

| 参考轮次 | 叙事任务 |
|---|---|
| 第1—3轮 | 建立身份、称呼、接触缘由和具体情境，明确双方关系与当前问题 |
| 第4—7轮 | 提出具体请求或危险操作，回应疑问，推进说服，出现首次付款意向或小额行动 |
| 第8—12轮 | 展开追加、拒绝、核实、矛盾、反证等主要交锋，分值与资金出现关键变化 |
| 第13—15轮 | 回应遗留问题，形成最终行动和态度，交代资金结果，完成收束 |

验证15轮故事时重点观察：

- 每轮是否有实际推进，是否反复重复相同内容或答非所问。
- 分值变化是否与受害者本轮实际表现一致，是否存在只解释未生效、重复解释仍加分。
- 首次付款是否过晚，付款后是否仍有足够的交锋和收束空间。
- 出现质疑和反证后，剧情是否作出合理回应，是否用催促或重复解释绕开。
- 最后是否完成收束，而不是停在等待材料、等待回应或准备核实的中间状态。
- 允许某场不付款、不展示全部诈骗环节；不要求每场都发生付款或识破。

### 10.5 规则统一与异常处理

BR-P06的共用处理如下：

- 同一账号同时只允许一场活动演绎。已有演绎进行中时阻止新建并提示，不替换旧演绎。管理员演示测试场次同样受单场活动限制，但只由本人访问。
- 第15轮完成前主动离开演绎页、刷新、关闭页面，按观看用户主动退出处理，属于正常业务结束；已有完整轮时保留已保存内容并生成如实报告，只有开场或半轮时说明未形成可复盘内容；管理员演示测试场次在待确认期间刷新或关闭页面同样按主动退出处理，不恢复审阅；单纯切换标签页不主动终止。
- 演绎进行中打开设置界面属于暂停，不属于离开演绎页；在设置界面中刷新、关闭页面按主动退出处理；在设置界面选择“退出演绎”并确认，正式结束前按主动退出处理，正式结束后直接进入复盘且不回退。
- 对话、解说或风险生成失败且无法继续，或语音、动画故障，停止并标记技术故障中断；不以0分、虚构对话、缺失媒体继续冒充完整体验。
- 演绎中保存失败停止推进，明确提示未成功保存；只保证已保存内容可回看。第15轮胜负未保存成功就不能标记正式结束。
- 资金不足且没有其他可用来源时不结束演绎、不凭空补钱；受害者可继续拒绝、核实或只表达意向，剩余轮次照常完成。
- 不因角色不愿继续付款、识破或明确拒绝而提前结束；剩余轮次仍须有回应，直到第15轮收束。
- 管理员演示测试场次的待确认、重新生成、直接修改和规则提交失败，按对应错误反馈；未确认草稿不生效，不能以“已修改”代替正式保存。
- 场景规则提交失败不改变任何场次；提交成功后只影响之后新开的同场景场次，进行中的场次读取开始时的规则快照。
- 技术故障中断不续演、不生成正式报告、不自动重开；主动退出的正常业务结束不续演，但生成如实报告，同样不自动重开。再次体验创建新记录；已保存内容维持本人可见。
- 已结束演绎的报告失败与技术故障中断、正常业务结束分开，按第8.5节处理；成功报告不改写。

评分、胜负、资金、轮次和异常规则集中由本章及第8.5、11.5节定义。模块、流程、历史和验收使用同一口径；后续修改必须同步引用章节与验收，不得只改某一页面文案。

### 10.8 资金约束与资金结果（BR-P14，V3.3新增，V3.4修订，V3.5修订）

| 项目 | 已确认规则 |
|---|---|
| 本场可动用资金 | 开始时取受害者画像的“可立即动用资金”；普通预留与应急预留不自动计入本场可动用额度 |
| 资金使用顺序 | 可用资金→普通预留→应急预留；只在本次实际决定执行的付款差额不足时释放对应预留，不一次性释放全部预留 |
| 小额上限 | 每个受害者在每个场景有独立的小额上限（见第11.7节）；同时校验本次付款金额和本次付款后累计未退回本金，两项都不超过才按小额行动处理，任一项超过即为较大金额行动 |
| 普通预留 | 可用于符合小额门槛的小额行动，不要求一律达到较大金额门槛；本次付款或累计未退回本金超过小额上限时，按较大金额行动判断 |
| 应急预留 | 不论本次金额大小，动用应急预留均需较大金额门槛，并需要有符合人物背景的理由；达到条件也不代表必然愿意动用 |
| 支付 | 实际付款减少可用余额；不得支付超过当前可用余额的金额，不得为推进剧情凭空补钱或临时提高上限 |
| 退回本金 | 只有实际到账的本金退回增加余额；与付款分别记录并关联原付款；承诺归还、平台余额、未兑现收益不算到账 |
| 报酬 | 支持没有先前付款的小额任务报酬，以及本金以外的额外报酬；只有系统确认的实际到账才记流水、增加余额并形成兑现事件；口头承诺不入账 |
| 出款上限 | 退回本金与到账报酬共用每场300元总出款上限，不各有一份额度；退回本金另须≤其关联原付款、≤累计实际支付；报酬不受累计支付限制，没有先前付款也可以到账；冒充亲友借款不安排实际还款，未来归还承诺不记账 |
| 声称出款 | 骗子可声称大额返款或奖励以诱导继续投入，但声称只是话术，不写流水、不增加余额；实际出款应尽可能少，实际出款不得超过本轮声称金额（有实际出款时声称必填） |
| 实际净损失 | 实际净损失＝max（0，累计实际付款－累计退回本金－累计到账报酬）；结果不大于0时视为没有净损失；零净损失不代表没有发生过需要分析的风险行为 |
| 追加次数 | 首笔垫付不计入；后续每笔实际追加投入计1次；重复提及或重复记录不能重复计数；报酬不冲抵追加次数 |
| 判断时点 | 每轮结束、全部已完成行为落库后汇总；同轮先付款后到账按轮末净额计算；资金事实不形成提前结束，第15轮胜负按最终净损失判定 |
| 首次受骗 | 首笔实际付款等受骗行为先记录，不立即结束，继续展示后续推进、追回或止损 |
| 资金不足 | 可用余额与尚可释放预留合计不足以覆盖某次拟付款时不执行该付款，不凭空补钱；演绎不结束，受害者可在剩余轮次拒绝、核实或只表达意向。余额为0但仍有可释放预留时不算资金不足 |
| 与受骗倾向／胜负的关系 | 资金余额、净损失、到账报酬和追加次数不参与五档风险评分；是否允许付款先受第10.9节付款门槛约束；第15轮胜负按第10.3节以最终受骗倾向分和实际净损失判定 |
| 允许拒绝付款 | 允许受害者领取小额奖励后拒绝继续付款，或在识破后停止付款，但仍须完成剩余轮次的回应；不得为凑金额、凑轮数或推进剧情迫使受害者继续投入 |
| 展示 | 资金摘要、三类预留情况与逐笔流水用于复盘、历史和报告；演绎页不新增独立资金面板 |

资金规则属于现有解说判定和固定业务规则的一部分；金额边界属于分场景人物画像配置，由管理员维护，不新增独立策略系统、评分体系或可编辑的资金策略库。

### 10.9 受骗倾向分、付款门槛与事件计分（BR-P15，V3.4新增，V3.5修订）

**用途与可见性**

| 项目 | 已确认规则 |
|---|---|
| 名称与范围 | 原名“信任分”，现统一称“受骗倾向分”；0—100整数，表达受害者因相信、压力、紧迫感或人情而让步的综合倾向，不等于五档风险，也不等于现实受骗概率 |
| 配置 | 初始分和正负向系数按“受害者×场景”配置（第11.7节），已经包含预设接触关系、场景和个人背景，不再额外叠加“熟人关系加分”；不按年龄或标签统一切分 |
| 可见性 | 骗子和受害者始终看不到分数、阈值和计分规则；观看者在实时逐轮解说中看到真实变化量和前后分，但看不到事件明细；第15轮结束后，报告和历史结果仅展示最终分与净损失，不展示阈值、系数或事件明细 |
| 保存 | 后台保存分数变化、事件依据和采用的配置，支持排查与测试；阈值、系数和事件明细不进入角色台词、解说或报告正文，观看者只在实时三栏解说中看到真实变化量和前后分；最终分仅随第15轮结束后的胜负结果返回 |
| 职责 | AI在完整一轮结束后识别事件并提供引用依据，程序计算分数；AI不自由决定当前总分，不能绕过计分增加分数，也不能直接写反证降分结果 |
| 结算时点 | 每轮以“骗子本轮发言／行动＋受害者本轮回应＋实际资金行为”的完整效果结算；不因骗子单方面给出解释就认定说服成功，也不在受害者回应前提前加分 |
| 生效时序 | 本轮开始时的对话、行动和付款资格使用上一轮已保存的分值；本轮结束结算的新分值从下一轮起影响对话、行动和付款资格。不得先付款，再通过补分满足门槛 |
| 不计分 | 不按轮次自动加分；付款本身不自动加分；重复表达、重复事件、没有新进展计0；同一次让步不能被多个事件重复计分 |
| 防重复 | 同一笔到账及其引起的“我放心了”只算到账事件；同一疑点持续存在不按轮次重复扣分；新的矛盾、新的有效解释、核实结果或新的心理变化可以形成新事件，并可用新的进展键区分 |
| 合并 | 同一轮多个独立事件分别计算，并按发生顺序逐个生效；不先把同轮增量相加再统一封顶；心理表现按正负事件分别保留，不只依据净变化生成 |

**人物参数候选（PC-P07，V3.5重校准）**

| 人物在该场景中的特点 | 初始分 | 正向系数 | 负向系数 |
|---|---:|---:|---:|
| 较易受影响 | 50 | 1.2 | 1.0 |
| 中等 | 45 | 1.0 | 1.0 |
| 较谨慎 | 40 | 1.0 | 1.2 |

九组默认配置从上述三类中取值，按“人物＋场景”逐组配置，不单凭年龄划分；同一人物在不同场景可以采用不同参数。三行均为候选值，需结合15轮完整故事验证后校准，不能当作已获数据验证的现实概率。九组映射见第11.7节。

**普通事件基础分（V3.5重校准）**

| 事件 | 基础分 |
|---|---:|
| 新的有效解释、专业解释 | ＋3 |
| 疑虑被化解、相关新材料产生有效影响 | ＋4 |
| 承诺实际兑现 | ＋5 |
| 独立支持或让步 | ＋2 |
| 独立质疑、回避回应 | －3 |
| 新矛盾 | －6 |
| 重复且没有新进展 | 0 |
| 反证成立 | 特殊降分，见第10.10节 |
| 反证解除、恢复普通计分 | 0（不额外加分） |

正向事件乘该人物该场景的正向系数，负向事件乘负向系数；系数默认1.0。取整由程序完成，事件按发生顺序逐个生效：每个事件从当前分出发加上取整后的变化，超过100按100、低于0按0处理，实际生效的变化记入该事件；同一轮多个事件依次生效，不先把它们相加再统一封顶。结果不向角色展示。只有未被事件计分覆盖的独立态度变化，才计算态度分。

**付款门槛（全局默认，管理员可调）**

| 分值 | 付款权限 |
|---:|---|
| ＜70 | 不允许实际付款，可以表达付款意向、询问或继续交流 |
| 70—84 | 允许考虑小额付款，仍受该人物该场景小额上限、本次金额和累计未退回本金约束 |
| ≥85 | 允许考虑较大金额付款，仍受资金能力、金额、用途、疑点和个人意愿约束；动用应急预留仍需较大金额门槛和合理理由 |

- 另保留40作为“更倾向于接受身份、继续交流”的行为阈值，不直接授予付款权限。
- 达到门槛只是允许考虑，不代表必须执行；金额、用途、疑点、个人意愿和经济条件仍然影响决策，最终资金行动由程序校验。
- 低于70不意味着可以无新依据反复询问同一个身份问题；85也不代表无条件服从。
- 本轮使用上一轮已保存的分值；本轮结束后结算的新分值从下一轮起影响付款资格。已完成的付款保留事实，事后降分不撤销记录，也不自动退款。
- 反证成立可以触发停止资金行动，不必等最终总分降到某个值。
- 阈值修改只影响新开始的演绎；进行中和历史演绎沿用启动时的阈值。
- 最终胜负分界80为固定业务规则，与付款门槛70／85分开；不得为了胜率把80改成可配置项或事后改分。

**参数校准与验证要求：** 初始分、人物系数、普通事件分值和“初始分减20”均为候选参数，必须与15轮故事节奏一起验证：检查分值是否上涨过快、扣分是否过弱、首次付款是否过晚、出现质疑和反证后剧情是否有足够交锋空间、第15轮能否收束。不能只看某一场是否出现骗子胜或受害者胜，也不能为了达到骗子总体获胜更多的默认演示效果而改分、放宽门槛或让受害者忽略明确反证。

**角色侧表达**：程序把受骗倾向状态转换为基于已知事实的自然心理倾向（如“对方兑现过一次承诺，你因此更放心，但新出现的资料矛盾还没有解释清楚”），不展示分数、阈值或“可以转账”的提示，也不用心理提示强制付款。

**旧记录：** V3.4及更早的信任分、60／80／90阈值、旧事件分值和“骗子本轮事件在受害者回应前生效”按当时规则展示和复算，不批量改写为新名称或新参数。

### 10.10 反证、降分与计分限制（BR-P15续，V3.5新增）

**反证分档**

| 反证情况 | 处理方向 |
|---|---|
| 有依据，但仍存在可验证的合理解释 | 降至该人物该场景的初始受骗倾向分 |
| 已可靠确认骗局，难以合理推翻 | 降至初始受骗倾向分减20 |

- 两档都只降不升：目标值低于当前分时，`delta = 目标值 − 当前分`；当前分已经更低时保留当前分，`delta = 0`。
- 初始分减20低于0时按0处理。
- 反证降分不受正向／负向系数影响，不按普通事件基础分计算；事件记录保存反证类型、目标值、变化前后分数和原文依据。
- 普通疑点、回避回应和一般矛盾继续按普通事件扣分（－3、－3、－6），不与反证降分重复计分。
- 反证可以由受害者台词、动作说明、已提供材料、亲友反馈或实际资金事实支持；骗子单方面否认或催促不构成反证。

**反证成立状态**

- 反证成立后，该场进入“反证成立状态”：骗子新的普通解释、承诺、催促或重复说法不增加受骗倾向分；相关正向事件可以记录为依据，但实际增量为0。
- 骗子不能绕开反证，通过换话题、重复解释或催促恢复加分；只有有效回应反证、解除其造成的限制后，才恢复普通计分。
- 恢复普通计分本身不额外加分；恢复后发生的新有效解释、疑虑化解或承诺兑现，按普通事件从当前分继续计算。
- 反证成立状态不自动结束演绎、不自动判定受害者胜，也不跳过剩余轮次；它影响分值、付款资格和剧情走向，最终仍按第15轮结果判定。
- 同一反证主题已成立后，同档重复不重复降分；同一主题有新的可靠确认依据时，允许由“有依据但仍有合理解释”升级为“可靠确认骗局”一次，以人物＋场景初始分减20（下限0）为新目标，只降不升。当前分更低时保持不变；旧请求重试或降档不重复扣分。升级不解除该主题或其他主题的限制；新的、独立的可靠反证可以形成新事件。
- 反证成立状态、目标分和恢复依据只保存在后台与事件记录中，不向骗子、受害者或观看者展示状态名、目标分或事件明细；观看者只看到已保存分析投影的本轮变化量和前后分。

**示例（仅示意，不作为固定台词）：**

- 受害者从原有号码联系到被冒充的亲友本人，本人明确否认借款：可靠反证，降至初始分减20；此后骗子重复“你听错了”“先别管他”不恢复加分。
- 受害者发现材料日期与骗子先前说法矛盾，但骗子提供了可核验的更正说明：有依据但仍存在合理解释，降至初始分；若更正说明有效，反证限制可解除，之后的新解释才可正常计分。
- 受害者只是说“我觉得不太对”但没有依据：按普通独立质疑－3处理，不触发反证降分。
- 受害者已付款后才发现被骗并追回：反证可降分并影响后续付款，但已发生的付款、退回本金和到账报酬照实记录，不删除过程事实。

### 10.11 等待事项与外部反馈（BR-P16，V3.4新增，V3.5修订）

| 项目 | 已确认规则 |
|---|---|
| 记录内容 | 记录提出了什么要求、依据是什么；状态包括尚未反馈、已经反馈、要求已满足、暂时无法取得结果、主动不再等待 |
| 持续保存 | 状态持续保存，不每轮重新开始同一件事；已经满足的要求不再无依据重复提出 |
| 咨询亲友的触发 | 是否咨询亲友综合受骗倾向、人物决策习惯、经济负担和具体疑点判断，不单凭分数决定，也不设简单全局咨询阈值 |
| 亲友反馈来源 | 由场景规则提供，不新增亲友Agent；只有实际发出咨询才触发，不把“准备咨询”当成已经咨询 |
| 亲友反馈时点 | 在下一次受害者回应前提供具体回复或明确的暂时联系不上结果 |
| 亲友反馈内容 | 依据场景和客观事实，不由受骗倾向分决定真假；受骗倾向影响是否继续等待和怎样理解回复，不改变外部事实 |
| 不得暗示已核实 | 不再等朋友意见、朋友没有回电或暂时联系不上，都不等于朋友已经核实可靠；真正的亲友没有提出借款，不能因受骗倾向分高就生成“他确认确实借款” |
| 材料要求 | 已补齐清晰完整材料，就结束“信息缺失／模糊”问题；完整不等于真实，真实性疑虑可以另行保留 |
| 材料边界 | 不无依据重复否认已提供内容，也不强制每次补充材料后再生成新疑点；第一版只用模拟材料内容和明确状态，不新增真实图片生成或识别，不制作真实可用凭证 |
| 材料信息 | 模拟材料中的信息必须明确（如金额、日期、户名、用途），不能只写一句笼统的“已提供证明”就自动通过所有判断 |
| 等待期间 | 可以继续了解其他信息，但必要核实不能因超时自动视为通过；主动不再等待不等于外部事实已经核实 |
| 最后一轮 | 第15轮结束前必须把未结事项收束为明确结果（已满足、无法取得、主动不再等待或仍拒绝），不能停在“等待材料／等待回应”的中间状态 |

**亲友反馈的场景规则（PC-P08）**：第一版为代码内固定规则，按“场景×咨询对象”给出回复；后台不可编辑，不按受害者或受骗倾向分改变，也不新增亲友Agent。

| 场景 | 咨询对象 | 回复性质 | 回复示例 | 对受骗倾向与结论的影响 |
|---|---|---|---|---|
| 冒充亲友借款 | 通过原有号码联系被冒充的本人 | 真实本人否认 | “我没跟你借过钱，也没换号，你别转。” | 可靠反证，可触发停止付款或形成识破过程事实；不自动结束演绎；不得写成“他确认确实借款” |
| 冒充亲友借款 | 咨询其他家人或朋友 | 转达或联系不上 | “他说没这回事，你直接打给他确认。”／“我暂时联系不上他。” | 中性，只影响是否继续等待，不直接判定真假 |
| 刷单返利 | 咨询同学、家人或邻居 | 中性提醒 | “我没做过这种，先别付钱，问清楚再说。” | 不判定真假，只影响是否继续等待 |
| 虚假投资 | 咨询家人、朋友或银行熟人 | 中性提醒或建议走正式渠道 | “我不懂这个，建议你去银行问。” | 不判定真假，不改变外部事实 |

回复规则：

- 只有实际发出咨询才提供回复；未发出咨询、只表示“准备问一下”不触发。
- 回复在下一次受害者回应前给出，包含具体内容或明确的“暂时联系不上”，不能省略为已通过。
- 联系不上、放弃等待、不再等朋友意见，都不等于核实通过，也不改变外部事实。
- 回复文本不出现分数、阈值、“系统核实”或“已确认对方身份”等表述。

## 11. 业务对象与信息需求

### 11.1 三类核心业务信息集合

| 信息集合 | 业务内容 | 关系 |
|---|---|---|
| 场景 | 名称、简介，表达诈骗类型 | 用户选择，管理员维护固定三项文案 |
| 画像 | 骗子及受害者人物信息、基础事实、三套场景资料、行为参数、情境与可用状态 | 用户双方各选一个，管理员维护和扩充 |
| AI情景演绎 | 当时完整配置与规则快照、对话、解说、风险与依据、受骗倾向事件与分数变化、等待事项、资金流水与净损失、过程状态、最终胜负与过程事实、正常业务结束原因、技术故障中断原因、对应报告及状态 | 关联同一次体验和所属用户 |
| 干预与场景规则 | 待确认草稿、已采用干预（原台词、干预要求、最终台词）、待入库记录、场景级规则及其来源关联、规则启用状态和版本 | 管理员本人演示测试场次与后台维护；普通用户未来仅本人当前场次、不入库 |

这些是业务信息集合，不等同于四个物理数据库，也不限定系统只有四张表。账号是身份和内容归属依据。场景深度卷入参考属于第10.3节的复盘说明，不因此给场景管理增加目标编辑或流程、策略管理能力。资金规则和受骗倾向计分属于固定业务规则，不形成独立策略系统或评分体系；分场景受骗倾向参数与金额边界随画像维护，40／70／85阈值由“受骗倾向机制管理”维护，场景规则由“场景知识库”维护。

正式场景内容（PC-P01）：

| 场景名称 | 场景简介 | 内容侧重 |
|---|---|---|

### 11.4 过程、结果与状态的对应关系

- 一次演绎关联一个用户和一组当时完整配置，保留当时场景名称、简介及双方全部人物信息，包括基础事实、三套场景资料（本场使用当前场景）、本场使用的初始受骗倾向分、正向系数、负向系数、小额上限和40／70／85阈值、头像内容、行为参数、故事时间与情境，以及开始时启用的场景规则快照。
- 对话、解说、风险及依据按实际顺序对应轮次；受骗倾向事件、分数变化和等待事项按实际发生顺序关联轮次和消息；资金流水按实际发生顺序关联轮次和消息；未完成轮保留已有内容并标明不完整。
- 演绎过程区分进行中、正式结束（完成15轮并判定胜负）、无胜负的正常业务结束（观看用户主动退出）和技术故障中断。正式结束关联“骗子胜／受害者胜”之一；正常业务结束写明“未形成胜负结论”；技术故障中断关联故障原因；不能用中断替代胜负，也不能把未完成15轮写成骗子胜或受害者胜。
- 主动退出的正常业务结束只有在至少存在一个经服务端确认的完整轮时才生成报告，包括无胜负结论的情形。没有完整轮时不生成报告、不开放重试，显示“未形成可复盘内容”；已有完整轮后在后续半轮退出仍生成报告，保留半轮实际内容但不补造缺失内容。报告状态为生成中、已完成或生成失败；技术故障中断明确显示无正式报告，不能伪装成报告生成失败以开放重试。
- 复盘与历史引用同一次风险、受骗倾向状态、资金事实、最终胜负与过程事实。实际受骗行为、实际净损失、当前风险、受骗倾向状态、胜负分别表达，不相互覆盖；受骗倾向分和事件明细不进入用户可见内容。
- 干预草稿只属于待确认过程，不进入正式对话、历史对话或报告；已采用干预、待入库状态和场景规则按第15章保存；规则快照随演绎保存，不因之后规则修改而变化。
- 旧记录保留原结果名称、原资金口径和原报告结构；新会话使用V3.5规则、胜负结果与报告结构，两者按规则版本区分展示。

### 11.5 保存及历史一致性

保存规则（BR-P08）：

1. 每段完整角色对话、每轮解说与风险均在保存成功后正式展示；胜负结果或结束原因、资金流水、受骗倾向事件和等待事项产生后分别保存。不能先展示为正式内容，再静默丢失保存结果。
2. 保存完成15轮的正式结束、主动退出的正常业务结束和技术故障中断演绎的实际已保存内容。半轮可保留，不补造缺失回应、解说、评分、资金或结果。
3. 演绎中保存失败时停止推进，明确说明未成功保存的情况；只承诺已保存内容可回看，不显示“全部已保存”等错误成功状态。
4. 报告保存失败不能显示报告已完成，不改变已结束的演绎；按报告失败状态提供同次报告重试。
5. MVP无自动到期清理，不设置用户删除入口；不保存或回放整段角色语音、动画。
6. 前端舞台随轮次清理气泡只改变当前显示，不删除、覆盖或修改已保存的对话、解说、风险、受骗倾向事件与资金流水，也不发起删除操作；后台预先准备但尚未轮到呈现的内容不属于已保存内容，技术故障中断、正常业务结束或正式结束时丢弃。未确认的干预草稿不属于正式内容，不随历史对话展示。
7. 资金流水与轮次资金摘要必须在同一短事务中保存，余额、净损失、退回本金、到账报酬、三类预留和追加次数以流水为准；不得只保存汇总而丢失逐笔依据。
8. 受骗倾向事件与分数变化必须在本轮完整内容保存后、以本轮为边界结算保存；被拒绝的候选回应、重新生成的回应和重试请求不得重复计分、不得留下孤立事件。同一事件只能计分一次。反证降分、反证成立状态和恢复计分依据必须在同一事务中保存。
9. 付款门槛校验与资金动作同事务执行：不满足门槛、超出小额上限或超出可用资金的付款不落库，也不得先记“已付款”再补校验。本轮付款使用上一轮已保存分值；本轮结算的新分值不得倒推用于本轮已发生的付款。
10. 已采用干预与正式骗子消息对应保存；未采用草稿可覆盖或丢弃，不进入待入库列表；场景规则提交与来源记录关联在同一事务保存，规则快照在开始演绎时冻结。

历史一致性（BR-P10）：基础场景和画像后续编辑、停用、重新启用、阈值调整或场景规则修改，不改变正在进行或历史演绎中的当时完整配置，不重新生成历史风险、受骗倾向分、资金事实或替换原报告。初始画像数量可增加，但历史始终保持原对应关系。旧会话的快照、结果、报告、规则版本和Prompt版本保持原样，不批量重写。

历史展示（PC-P05）：列表显示开始时间、场景、双方画像名称、演绎状态、报告状态；详情展示当时完整配置、按顺序排列的对话与解说、已有风险与按轮颜色边条（颜色取本轮结束时已保存风险）、资金摘要与三类预留、最终胜负与过程事实、正常业务结束原因、技术故障中断情况及报告入口。全部对话放在固定高度可滚动框内，默认从第1轮开始。未完成轮明确标注；风险图只使用实际评分，不将缺失值补为0；已评分轮次不显示风险数值或文字标牌，未评分显示灰色“未评分”。无记录时显示本人暂无记录，不使用他人内容或虚构记录填充。历史列表和详情不展示过程分、阈值、系数或事件明细；第15轮结束后的历史结果可展示最终分与净损失；等待事项内部状态仍不展示；管理员本人演示测试记录可显示待入库干预入口，但不展示任何普通用户数据。

媒体最低要求（PC-P04）：

- 半身立绘待机浮动、说话时嘴部开合（闭嘴／张嘴两帧切换）与轻微身体动作，当前发言角色突出；情绪表情及复杂动作增强为未来方向。
- 骗子先发言、受害者再回应，语音顺序播放不重叠，双方声音可区分且同场固定，文字与语音内容一致；台词随语音进度逐步显示并按分句对齐；动作说明不朗读。
- 角色语音使用Qwen-Audio-3.1-TTS-Flash（模型标识`qwen-audio-3.1-tts-flash`，中国北京地域）；按性别与年龄段映射预设音色，中老年听感须实际试听确认，不能仅凭音色名称认定符合。
- 解说为文字，每轮回应后呈现分析、风险与依据，不提前剧透下一轮。
- 风险颜色固定为100红、75橙、50黄、25蓝、0绿、未评分灰；复盘和历史按整轮使用彩色边条，已评分轮次不显示风险数值或文字标牌，正文不整体染色。
- 声音开关位于设置界面，静音不影响其他内容，也不视为语音失败；提供设置暂停与继续，无中断后续演、倍速、回放。
- 本轮语音完成、解说与风险均展示后，正常停留5秒，再进入下一轮或复盘；不因取消时长上限而缩短或取消阅读停留。
- 语音或动画故障导致中断，不能将媒体持续缺失的体验计为正常验收通过。
- 场景介绍动画不超过15秒，双方人物卡合计不超过8秒；两者仍计入正常演绎过程，但不再由600秒业务上限约束。

已知限制均已在评审中明确：密码允许6—24个字符和常见弱密码，账号更易被猜中，个人记录存在相应访问风险；本版取消600秒业务上限，固定15轮必须完整完成，单步生成或媒体故障仍可能导致中断且没有正式复盘。新会话的正式结果只有“骗子胜／受害者胜”；观看用户主动退出形成无胜负结论的正常业务结束并生成如实报告；技术故障中断不生成报告。旧记录中的“已受骗／已识破／超限结束／未受骗结束／结局未定”按当时规则展示。报告默认约400—600字，极端情况下可能因内容不足或超限而失败重试。受骗倾向参数是模拟初始配置，不是现实受骗概率，也未经数据验证；阈值、系数、事件分值和“初始分减20”需要在真实15轮演绎中校准，调整必须说明观察到的问题和依据，不能以单场胜负作为唯一依据。魔法球在MVP只对管理员本人演示测试场次开放，普通用户当场干预为未来能力；场景规则只影响之后新开的同场景场次。亲友反馈按场景规则给出，第一版不提供真实图片生成或识别。Qwen语音在开发验收阶段试听预设音色，具体音色、参数和音频格式仍待实现阶段确定。

本版量化业务指标为固定15轮（30次角色发言）、通常5秒阅读停留、场景介绍15秒与人物卡8秒上限、台词约50字与解说每项约40字的长度目标、复盘约400—600字且最多3个关键节点和2—3条建议、账号长度和立绘上传限制；另有受骗倾向分0—100、全局阈值40／70／85、最终胜负分界80、每场出款上限300元、九组初始分／系数／小额上限和三类预留金额。其他模型性能、具体语音服务、同步实现和资源配置由技术文档承接，不能因此改变本版用户结果与失败处理。

## 14. 情景演绎演出层要求（V3.2新增，V3.3修订）

本章集中规定AI情景演绎页面的演出体验，是FR-SIM-01至FR-SIM-11、PC-P04、PC-P06、PC-P09、BR-P13、BR-P17、BR-P18的细化。本章只规定用户可见效果与业务约束，不规定动画引擎、语音模型或实现方式。整体表现参考2D剧情游戏与视觉小说：持续推进的角色演出，而不是不断累积消息的聊天界面，也不以生成完整视频为前提。

### 14.1 开场流程

| 步骤 | 要求 |
|---|---|
| 进入演绎页 | 从配置页点击“进入演绎”进入；加载所选场景的介绍动画资源及双方立绘资源，显示清晰的等待状态；此时不建立演绎记录 |
| 开始演绎 | 资源就绪后显示“开始演绎”按钮；点击即校验配置、建立演绎记录；本版不设600秒业务计时 |
| 场景介绍 | 播放所选诈骗场景的介绍动画，同时展示本次场景名称与简介（取当时配置）；动画围绕所选场景，不使用与场景无关的通用动画；不超过15秒 |
| 人物卡 | 展示骗子、受害者人物卡：半身形象、姓名、性别、年龄、身份，均来自当时配置；合计不超过8秒 |
| 正式演绎 | 进入左右舞台，开始第1轮 |

三个固定场景各有一段介绍动画，动画画面不随管理员编辑名称简介而变化；画面上的名称与简介文字取当时配置。

### 14.2 舞台布局

- 主体为角色舞台：左侧骗子、右侧受害者，中间有明显视觉分隔，左右位置全程固定，不随发言者互换。
- 双方各有独立对话气泡，骗子气泡在左、受害者气泡在右，与对应人物及说话状态明确关联。
- 舞台下方为独立的解说区与风险指数区，视觉层级与舞台区分。
- 顶部只保留设置按钮，不堆放其他控制项。

### 14.3 立绘与动画

- 角色使用半身立绘；每个画像具有闭嘴、张嘴两张同尺寸立绘（BR-P09）。
- 待机：自然姿态与轻微身体浮动。说话：闭嘴／张嘴交替形成嘴部开合，配合轻微身体动作；当前发言角色更突出，非发言角色保持待机、不抢注意力；说完恢复待机。
- 不要求骨骼动画、音素级口型或复杂面部表情。

### 14.4 发言呈现与同步

- 每轮顺序：骗子草稿→（管理员演示测试场次先待确认，确认后）正式骗子发言→受害者回应→本轮受骗倾向事件结算与解说风险更新→阅读停留→下一轮或第15轮判胜负。普通用户场次没有待确认步骤，草稿直接采用。
- 管理员待确认期间，舞台只展示草稿和“待确认”标识；受害者不出现、不生成；未确认草稿不得按正式台词样式呈现或朗读。
- 单次发言：角色进入说话状态→对应气泡出现→台词随语音进度逐步显示→语音结束、文字完整显示后恢复待机。
- 台词与语音在呈现前均已完整准备；逐步显示与语音进度保持一致，以分句为单位对齐，误差不超过当前分句；不得出现语音已到后半段而文字仍停留在开头等明显不同步。
- 角色的模拟行动（如“已完成转账”）以动作说明展示在对应气泡附近，不朗读；台词气泡只显示说出的话。
- 上一角色语音或必要动画未完成前，下一角色不得开始；双方语音不重叠。
- 单条台词以约50字以内为目标，后期可按剧情节奏适度缩短；气泡放不下时在气泡内滚动，不截断已保存内容。

### 14.5 气泡保留与清理

- 骗子发言时显示左侧气泡；受害者回应时显示右侧气泡并保留左侧气泡；本轮解说与阅读停留期间双方气泡继续保留。
- 下一轮开始时清理上一轮的舞台气泡。清理只改变前端当前显示，不删除、清空、覆盖或修改已保存的历史对话，也不发起任何删除操作；历史记录与复盘始终读取完整保存内容，不依赖舞台上是否还显示某个气泡。

### 14.6 底部解说区与风险节点条

- 每轮受害者回应完成后展示本轮三栏解说：左栏“骗子的手段”使用2～12字短标签，中栏“骗子想做什么？”使用12～40字意图句，右栏展示真实受骗倾向变化（本轮变化量、轮初分→轮末分、上升／下降／不变趋势）；另保留受害者心理与风险依据。仅文字，不播放语音；须有实际分析意义，不复述台词，不能只给分值。完整话术与手段分析另行保存，供复盘报告和历史详情使用。
- 风险以0、25、50、75、100五节点条独立展示，高亮当前档位并同步显示依据；开场显示“尚未评分”；评分规则遵循第10.2节，不另行定义。受骗倾向分与风险节点条不合并、不互相换算。
- 风险颜色固定为：100红色、75橙色、50黄色、25蓝色、0绿色、无评分灰色并标注“未评分”。实时节点条保留分值。
- 下一轮演出期间，解说区继续显示上一轮解说并标注所属轮次，风险节点保持上一轮档位，直至新一轮解说与风险替换；不提前展示下一轮内容。

### 14.7 后台预备与等待

- 系统在前台演出的同时预先准备后续内容：开场期间准备第1轮骗子草稿；骗子发言期间准备受害者回应及语音；受害者回应期间准备本轮解说与下一轮骗子草稿。
- 预先准备的内容在轮到其呈现前不展示，也不作为已保存的正式内容；本轮形成正式结束、正常业务结束或技术故障中断时，未呈现的预备内容直接丢弃，不形成额外角色对话。
- 阅读停留正常5秒；停留结束时下一轮骗子草稿尚未就绪，显示轻量等待状态，就绪后立即开始；不无限延长停留，不为赶时间跳过台词或语音。等待不改变轮次、分值或胜负。

### 14.8 角色语音

- 使用Qwen-Audio-3.1-TTS-Flash（模型标识`qwen-audio-3.1-tts-flash`，中国北京地域）；按画像性别与年龄段自动匹配预设音色（第11.3节），双方可区分、同场固定。
- 预设音色在开发验收阶段由需求方试听，重点检查中老年听感，不能仅凭音色名称认定符合；用户与管理员不单独选择音色。
- 骗子表达具有一定主动性和引导感，受害者表达自然；语速、停顿和语气可随剧情轻度变化，不要求复杂情绪语音。
- 静音时语音不发声，台词逐步显示、动画、解说与流程按同一时间进度正常运行。
- 台词朗读、动作不朗读；分句同步、暂停和播放顺序保持现有规则；语音等待与播放不改变轮次、分值或胜负，终止后不播放迟到内容，失败不能冒充正常完成。

### 14.9 设置界面

设置界面独立显示于舞台之上，提供声音开关、继续演绎、退出演绎三项；退出需二次确认。暂停与退出规则见BR-P13（第10.7节）与BR-P06；本版不按暂停时长顺延任何业务截止时间。

### 14.10 待确认与魔法球入口（V3.5新增）

- 仅管理员本人演示测试场次显示待确认状态、魔法球入口和待入库记录入口；普通用户演绎页不显示这些控件。
- 待确认状态位于舞台上方或侧边，明确标注“本轮草稿待确认，尚未影响受害者”；“继续”采用原稿，魔法球用于重新生成或直接修改。
- 魔法球打开后不遮挡对当前草稿的查看；关闭魔法球不改变草稿或演绎状态；具体两区结构见第15章。
- 待确认、审阅和规则提交不改变风险节点条、五档解说区或历史数据；未确认内容不进入历史对话。

## 15. 演绎当场干预与场景知识库（V3.5新增）

本章规定演绎页魔法球、已采用干预的待入库记录、场景规则归纳提交、规则生效与后台维护。它是FR-SIM-10、FR-SIM-11、FR-ADM-06至FR-ADM-08、BR-P18、BR-P19的细化，不新增独立Agent、通用知识库或自动改分能力。

### 15.1 定位与角色边界

| 项目 | 已确认规则 |
|---|---|
| 入口位置 | 魔法球直接位于演绎页，不需要进入管理后台；管理员在本人演示测试场次观看演绎时即可使用 |
| 本版角色 | 仅管理员本人演示测试场次可用；普通用户在本期不能使用，未来按FUT-03只影响本人当前场次 |
| 后台分工 | 演绎页魔法球负责当场干预、查看本人待入库记录、归纳并提交规则；后台场景知识库负责查看、编辑、启用／停用已提交规则 |
| 作用范围 | 当次干预只改本轮骗子台词；规则只约束之后新开的同场景场次；不能改写已经保存的历史对话、分值或资金 |
| 干预能力 | 可以改变表达、策略和请求；不能凭空创造到账、退款、付款、余额变化等实际资金事实，不能绕过付款门槛、余额校验和反证限制 |
| 数据边界 | 未确认草稿不属于正式内容；只有最终采用的版本保存为骗子消息并参与受害者回应、受骗倾向计分和资金处理 |
| 权限边界 | 管理员只能打开本人测试场次；不得通过魔法球、待入库列表或规则库读取任何普通用户场次、历史或报告 |

魔法球不是聊天输入框，也不是让管理员代替骗子整场写台词的工具。它的职责是把本轮不合理的话术纠正到“身份、称呼、事实一致，回应当前问题，剧情合理连贯”，并把可复用的纠正沉淀为场景规则。

### 15.2 当场干预流程

1. 每轮系统先生成骗子草稿。普通用户场次直接采用；管理员演示测试场次进入待确认状态，舞台展示草稿，受害者不生成、不回应。
2. 管理员判断草稿是否合理：
   - 合理：点击“继续”，草稿成为本轮正式骗子台词，随后生成受害者回应。
   - 不合理：点击魔法球，输入指导让AI重新生成，或直接修改台词；可以反复重新生成和修改。
3. 管理员确认最终版本后，系统保存正式骗子消息及其允许的资金动作，再生成受害者回应。确认请求必须携带草稿ID和期望修订号；服务端只接受当前轮的当前草稿，旧轮或旧修订返回冲突，重复确认同一草稿返回既有结果。受害者针对最终确认版本回应，不针对被丢弃的旧版本。
4. 修改的是本轮刚生成的骗子台词，不等到下一轮生效；下一轮仍重新生成草稿并再次等待确认。
5. 未确认版本不保存为正式消息，不影响受害者回应、受骗倾向事件与分数、资金流水、余额、胜负或报告；刷新或退出按主动退出收敛，未确认草稿不生效、不恢复审阅，也不补造受害者回应。
6. 直接修改和重新生成都要经过内容校验：角色归属、是否回应本轮问题、是否与前文身份／称呼／事实一致、是否引入未发生的资金事实、是否出现系统提示或内部规则文本。校验失败时保留原草稿并提示，不静默采用。
7. 干预审阅不设时长上限，也不累计任何业务计时；审阅多久都不改变轮次、分值和最终胜负。

**资金事实边界：**

- 草稿或修改稿可以声称“已经返款”“马上到账”“平台显示收益”，但这些只是话术，不写资金流水、不增加余额。
- 实际退回本金、到账报酬、付款和预留释放仍由结构化资金动作和程序校验决定；文字修改不能新增、放大或改变实际出款。
- 修改稿声称的金额不得与实际已发生的流水矛盾；实际出款不得超过本轮声称金额的既有规则不变。
- 修改稿不能把未发生的付款写成已发生，也不能把已发生的付款删掉；已发生事实以资金流水为准。

### 15.3 待入库记录

魔法球包含两个主要内容区：

| 区域 | 内容 | 数据规则 |
|---|---|---|
| 当场干预 | 当前轮草稿、干预要求输入、重新生成、直接修改、继续／确认 | 只保留当前草稿；被替换的草稿不累积成历史列表 |
| 待入库记录 | 已采用干预的列表，逐条显示原台词、干预要求和最终台词，可勾选 | 只保存最终采用的版本；未采用的重新生成尝试不进入列表 |

- 只有最终采用、且确实替换了原台词的干预才进入待入库记录；直接点“继续”采用原稿不产生记录。
- 每条记录至少包含：场景、轮次、原台词、干预要求、最终台词、采用时间和来源场次；不保存管理员每次临时指令的完整流水。
- 记录状态为“待归纳”或“已关联规则”。归纳提交后记录移出待入库列表，但仍可按规则查看来源。
- 待入库记录只显示管理员本人演示测试场次产生的数据，不显示普通用户场次；普通用户未来干预不进入该列表。
- 列表按场景筛选，默认按采用时间倒序；同一轮只保留最终采用的一条记录。

### 15.4 规则归纳与提交

1. 管理员勾选一条或多条待入库记录，点击“归纳规则”。系统生成一条规则草稿，归纳共同问题，不复制某一句临时指令。
2. 管理员编辑规则标题和正文，确认其是可复用约束；本期只做合并，不做拆分。确认后提交场景知识库。
3. 相同问题合并为一条规则，来源关联保留多条记录；一条来源记录只能归入一条规则，提交后不支持把新来源追加到已有规则；来源用于追溯“这条规则从哪些具体修改中来”，不把具体人名、余额或临时状态写进规则正文。
4. 提交前校验：规则属于一个固定场景、正文非空、至少关联一条待入库记录、正文不是对某场台词的逐字复制、没有包含普通用户数据或内部阈值。
5. 提交成功后规则默认启用，记录状态改为“已关联规则”；提交失败保留草稿和记录，不显示为已入库。
6. 系统归纳只是草稿，不能自动提交；管理员必须编辑确认。规则正文不出现“系统要求”“模型必须”等内部实现措辞，应写成对骗子话术的可复用约束。

**归纳示例（仅示意）：**

| 具体干预 | 可复用规则 |
|---|---|
| “这一场不要再叫对方叔叔，人物关系是同事。” | “称呼应与本场已经确定的人物关系保持一致；不得使用与关系不符的亲属称谓。” |
| “受害者问的是到账时间，不要重复讲任务规则。” | “应优先回应当前问题；同一轮不得用重复介绍规则代替具体答复。” |
| “上一轮说自己在公司，这一轮不要又说在家。” | “地点、身份和已披露事实应与前文一致；改变说法时必须给出可核对的解释。” |
| “不要每轮都催，受害者已经说要核实了。” | “受害者已明确核实或拒绝后，不得用重复催促替代对新疑点的回应。” |

规则应描述“应该保持什么、回应什么、避免什么”，而不是“这一场不要叫叔叔”“这一场说500元”这类只对单场有效的指令。

场景知识库的首要目标：

- 保持身份、称呼和已披露事实一致，避免同一人物在不同轮次自相矛盾。
- 回应当前问题，减少答非所问、重复介绍和空泛拖延。
- 让话术及剧情发展合理、连贯，使质疑、核实、反证和让步都有可理解的因果关系。

### 15.5 规则生效、快照与优先级

| 项目 | 已确认规则 |
|---|---|
| 生效范围 | 规则按场景生效；之后新开的同场景演绎把已启用规则加入骗子生成话术时的提示内容 |
| 快照 | 开始演绎时冻结当时已启用规则（ID、版本、正文）；本场全程使用该快照，之后新增、编辑或停用规则不影响本场 |
| 历史 | 已保存历史按当时规则快照和对话展示，不因规则变化重写；报告不重新判定 |
| 优先级 | 固定业务规则和已保存事实优先于场景规则；场景规则优先于一般文风偏好；规则不能改变身份事实、资金事实、付款门槛、反证判断或15轮胜负 |
| 冲突 | 管理员在提交或编辑并启用前人工确认同场景规则不冲突；程序只校验同场景标题、来源未关联与正文边界，不自动比较语义或“更具体”。所有启用规则按版本号降序、ID升序冻结并注入；该顺序只保证确定性，不代表跨规则语义优先级。固定业务规则和已保存事实始终优先；运行时规则冲突不导致场次暂停、中断或等待管理员 |
| 非检索 | 规则以结构化文本注入提示，不做向量检索、文档召回或通用RAG；规则数量应保持可维护，不为每句话建一条规则 |
| 禁止用途 | 不得用规则强行提高骗子胜率、让受害者忽略明确反证、绕过付款门槛或凭空生成到账退款；规则价值不以单场骗子是否获胜判断 |

规则注入骗子提示时，只提供规则正文和必要的场景标识，不提供来源场次的用户数据、管理员身份、受骗倾向分或阈值。骗子仍只能使用场景中合理可知的信息。

### 15.6 后台维护、普通用户未来边界与默认演示目标

**后台维护（FR-ADM-08）：**

- 按场景查看规则列表：标题、正文摘要、来源记录数、启用状态、版本和最近修改时间；可点开规则查看本人来源的原台词、干预要求、最终台词和来源场次。
- 可编辑标题和正文，可启用或停用；编辑产生新版本，已开始场次不受影响；不支持拆分规则或给已有规则追加来源。
- 停用后，之后新开的同场景场次不再使用该规则；已经开始的场次继续使用快照。
- 不提供普通用户记录、单场分数、事件明细或报告入口；不提供规则自动生成后直接启用、批量导入文档或向量检索。

**普通用户未来边界（FUT-03）：**

- 普通用户未来可以使用类似魔法球的当场干预，增加参与感；本版不开放。
- 普通用户的操作只影响本人当前场次：可以重新生成或修改本轮骗子台词，但不进入公共知识库、不修改长期提示词、不影响其他用户或之后的新场次。
- 普通用户干预是否需要确认后受害者回应、是否保存本人过程记录，由未来版本另行定义；不得据此提前开放本期入口。
- 普通用户不能查看待入库记录、规则草稿或后台规则库，也不能把本人修改提交为公共规则。

**默认演示配置与胜率目标：**

- 默认演示配置希望骗子总体获胜更多，作为演示效果和内容校准目标，不是硬性KPI，也不以单场胜负判断规则价值。
- 不得为了胜率改分、放宽付款门槛、让受害者忽略明确反证、删除过程事实或事后改判；胜负仍按第15轮最终分值与净损失。
- 规则是否有价值，重点看是否减少身份／称呼／事实矛盾、答非所问和重复，是否让质疑与反证得到合理回应，是否让15轮故事更连贯；胜率只是观察指标之一。
- 参数和规则调整应记录观察到的问题、调整依据和影响的场次；不得只凭一次骗子胜或受害者胜就下结论。
