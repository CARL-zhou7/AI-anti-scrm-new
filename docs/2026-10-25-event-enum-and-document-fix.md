# 第62场EVENT中断复核与修复

日期：2026-10-25。

## 已确认原因与证据范围

通过只读JDBC查询最新第62场：虚假投资，第5轮ANALYSIS_FAILED。前四轮完整，第5轮骗子消息1076已经完成呈现，受害者尚未生成。该轮发来订单/政策核对表，内容是企业简称、订单同比区间和政策截止月份，没有支付金额或收款户名。

用户补充日志明确EVENT第5轮三次均被invalid trust event拒绝。代码追溯该错误来自旧trustEvents方法捕获IllegalArgumentException，主要覆盖TrustEventType.valueOf、EvidenceSource.valueOf、requirement中的WaitingItemType.valueOf，随后统一替换为同一泛化错误。

因此可确认本场是枚举解析分支拒绝，不应归因于语音、前端或直接断言材料完整性校验错误。旧日志没有保留实际非法枚举值，数据库也不保存被拒绝模型输出，无法进一步确认是type、source还是requirement.type。测试使用人为构造的错误值复现同一代码分支，不宣称这些值就是本场实际响应。

## 为什么此前修复仍不充分

- 已接入纠错反馈，但模型只收到invalid trust event，不知道哪个字段、哪些值可以使用。重试上下文变化仍不足以指导修正。
- 另一个可复现缺口：V27在材料完整性过滤之前仍强制每项包含正整数金额与全部非空字符串。普通行业文档若返回缺省/null/空字段，会先抛异常，尚未进入“不完整材料可继续”的分支。此前只覆盖了字段齐全但内容含相对日期的情况，没有覆盖缺字段及非资金文档。
- EVENT是受害者回应前的必经步骤；重复生成不合规字段并耗尽既定次数，整场就按原规则进入分析失败。不能通过把任意错误结果当成空事件来掩盖问题。

## 本次代码修改

1. 将枚举解析改为受任务约束的共享校验。错误明确标识TrustEventType/type、EvidenceSource/source或WaitingItemType/type及其允许值；EVENT不能混入态度事件，requirement仅允许MATERIAL/INFORMATION。
2. 原有重试反馈自动携带这些精确说明，使下一次请求能够纠正。未增加重试次数，未接收任意未知枚举、未为未知类型做猜测映射，也未将错误事件自动改为events=[]。
3. 材料摘要只要求稳定subjectKey，其他四项可缺省或为null；空字符串、金额0均视为不能生成完整摘要。所有给出的字段仍检查类型与长度，未知字段拒绝。负数、非整数、字符串金额继续拒绝。
4. 仅当摘要金额为正整数、其余字段非空且明确、逐字证据完整时，才产生可交给材料完成逻辑的Material。普通研究资料、订单数据、政策表可继续作为原文事件存在，不需要捏造支付字段；缺摘要不表示没有收到原文材料。
5. 金额0的容错仅针对附加材料摘要，不是资金动作：FundAction、账本、行动门槛及严格完整材料校验仍要求合法正整数，未放宽资金入账。缺信息的材料不能置为SATISFIED。
6. 新增V28激活EVENT版本5（资源prompts/v5/event.txt），明确非资金文档与资金凭据的区别、三类枚举允许值及无事件时的合法空数组。V1～V27及旧模板不改；README当前版本与迁移集成检查最终版本断言同步为28。

## 简单验证

仅执行7项本地定向检查，全部通过，0失败、0错误：

- NonfinancialMaterialTest两项：第62场同类研究材料在字段缺省、null、空字符串、0金额/季度日期等情况下保留原文事件而不生成齐全摘要；类型、字段名、长度及金额格式仍严格拒绝。
- EventMaterialHandlingTest选择四项：不完整材料保持OPEN；完整材料及逐字证据仍校验；三类枚举分别给出精确错误且拒绝跨任务类型；非法事件经反馈后模型模拟输出合法events=[]可以在原次数内完成。
- MaterialSourceBoundaryTest选择一项：完整模拟材料仍可正常满足材料事项，不等于独立核实。

日志：backend/target/event-enum-and-material-test.log及对应Surefire报告。V28资源读取、校验和及Java编译通过，没有实库迁移验证。先前一次新增测试漏导入SpeakerRole导致编译未通过，补齐后以上最终定向检查通过。
