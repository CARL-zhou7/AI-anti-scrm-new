# V1.4 三阶段实现计划

> **执行说明：** 按任务顺序实施并逐项验收；本计划不依赖未安装的执行技能。本文是开发基线，不代表代码已实现或测试已通过。

**Goal:** 按“轮次与胜负 → 管理员干预 → 知识库与快照”三个可独立验收的阶段，把现有 V1.3 代码升级到 PRD V3.5 / 架构 V1.4 / 数据库 V1.4 / 接口 V1.4。

**Architecture:** 保留现有 Spring Boot 模块化单体、Vue 3 前端、SSE 和 Cookie/CSRF 边界。新增规则版本 `PRD-V3.5` 与 `trust-v3`，旧 `PRD-V3.4`/`trust-v2` 场次继续按旧规则读取；当前最新迁移为 V43，三阶段新增迁移使用 V44（核心结构）、V45（新事件与解说提示词）、V46（管理员干预）、V47（场景规则），不改已执行的 V1～V43。

**Tech Stack:** Java 21、Spring Boot 3.5.16、Spring Data JPA、Flyway、MySQL 8.0.45、JUnit 5、Mockito、Testcontainers；Vue 3.5、TypeScript 5.9、Vitest 5。

**Spec:** `docs/AI反诈情景推演平台_PRD_V3_2_正式开发基线版.md`（V3.5）、`docs/AI反诈情景推演平台_系统架构设计文档_V1_1.md`（V1.4）、`docs/AI反诈情景推演平台_数据库设计文档_V1_1.md`（V1.4）、`docs/AI反诈情景推演平台_接口文档_V1_1.md`（V1.4）

## Global Constraints

- 当前迁移历史已到 `V43`（V42/V43 是既有 Java 提示词迁移）；新迁移只从 `V44` 开始，不修改 V1～V43。尤其不重新添加 `simulation_trust_event.progress_key`、不回填已有进展键、不重建四列唯一键；现有 `V38__trust_v2_events.sql` 已完成这些操作。
- 新会话固定：`ruleset_version=PRD-V3.5`、`trust_ruleset_version=trust-v3`、`snapshot_schema_version=4`、`report_content_schema_version=4`、`fund_ruleset_version=funds-v3`。
- 旧会话：`PRD-V3.4`/`trust-v2`/snapshot 3/report 3 保持原值；旧报告按原结构读取，不批量重写、不补写 winner/final、不补建旧报告。
- 正常演绎固定 15 轮；第 1～14 轮不判胜负，第 15 轮完成后按最终受骗倾向分与实际净损失判胜负；取消 600 秒业务截止，只保留单步生成、TTS、保存和媒体播放的技术超时。
- **本次新增确认优先于原隐藏规则：** USER 与管理员本人 ADMIN_TEST 场次的逐轮解说均展示真实受骗倾向分：本轮变化量、轮初分→轮末分及上升/下降/不变趋势，通过既有 `Analysis.trustChange` 随已保存分析和 SSE 返回；不得使用示意数字。角色仍不可见数值、阈值、系数和计分规则；事件明细不对外发布。第15轮后报告与历史结果仍只展示最终分与净损失，不新增报告过程分明细，不重写旧报告。
- 管理员演示测试场次只能由本人创建和访问；普通用户场次不出现在任何管理员列表。
- 场景规则本期只合并不拆分；一条来源记录只能归一条规则；提交后不追加已有规则来源。
- 新依赖为零。所有 API 失败继续使用现有 `ApiResponse`/`ApiException` 封套和既有 HTTP 状态码。
- **执行与提交边界：** 后端命令在 `backend`、前端命令在 `frontend` 运行；进入下一步前检查命令退出码，首次测试失败须因目标行为未实现，而非环境/编译配置错误。记录开发前已有变更；下文提交命令只是文件范围示例，实施时逐文件检查差异，只提交本任务改动，不使用宽泛目录暂存混入用户已有工作。不执行迁移到开发者实际数据库，迁移验收只用隔离测试库。
- **阶段切换：** Task 1～5构成一次Phase 1开发交付，Task 5之前不发布中间版本；V45激活新提示词与Task 5切换新会话版本一起部署，旧场次仍读取已绑定ID。Task 6验收通过后进入Phase 2，Task 10通过后进入Phase 3。

## Review Focus

- **迁移不能重复改表。** V38 已有 `progress_key` 和四列唯一键；V44 只能追加缺失列、约束和校验，不能把已有 `progress_key` 覆盖成 `subject_key`。
- **旧报告不能统一按新版结束原因屏蔽。** PRD-V3.4 的 `USER_EXIT`、`FUNDS_EXHAUSTED`、`CHARACTER_EXIT` 已有报告行时仍要可读、可重试；只有旧规则本来不生成报告且确实无报告行时才返回 `LEGACY_NO_REPORT`。
- **暂停恢复不能用“恢复时是否已到期”判断。** 剩余 2 秒时暂停 30 秒，恢复后仍应保留 2 秒阅读停留；按暂停发生时的剩余时间计算。
- **旧轮草稿不能应用。** 第 3 轮的“继续”延迟到第 4 轮时，必须因 `draftId` 不属于当前轮而拒绝，不能推进受害者。
- **多条反证不能一次全解除。** “材料日期矛盾”和“亲友本人否认借款”同时成立时，解释日期只解除日期主题；全部有效反证解除后才恢复正向计分。
- **规则冲突不能让普通用户场次停住。** 管理员启用前负责处理语义冲突；运行时不自动比较“更具体”，不因两条启用规则冲突而暂停、中断或等待管理员。所有启用规则按 `version_no DESC, id ASC` 固定顺序进入快照，固定事实优先，场次继续。
- **解说数字必须来自已保存事件。** 仅在双方正式内容和本轮计分保存后展示；正负事件以实际轮初/轮末分求差，封顶、反证、无事件、SSE重复与跨轮保留不能使显示值失真；风险节点条与受骗倾向分分别标注，不互相替代。
- **整轮结算与重试：** V3.5不走`startVictim`中的提前事件提交；双角色原文与引用归属校验失败不写分。事件、分数、反证状态与分析同事务保存，空事件轮也以分析已保存为结算标记；重复或并发回调不得重复提交。对应Task 2的`RoundTrustV3FlowTest`。
- **版本边界：** 新字段严格校验仅作用于trust-v3；旧解析入口与旧构造器保持旧语义，不能以放宽旧版版本判断让新会话落入旧结局算法。对应Task 2的`TrustV3CompatibilityTest`和Task 3的`NoEarlyEndV35Test`。

## Plan Decisions（计划定稿前已采用）

以下 D6～D9 已由需求方于 2026-10-28 本次评审确认；文档更新不表示功能已实现或验收通过。

- **D5 多条反证：** 用 `simulation_trust_event.subject_key` 标识反证主题；`COUNTEREVIDENCE_RESOLVED` 事件的 `subject_key` 只解除同一主题；会话 `counterevidence_active` 表示仍有任意未解除主题。不新增反证表。
- **D6 规则冲突：** 不做自动语义优先级。提交/编辑时只校验同场景标题、来源未关联、正文边界；管理员在启用前人工确认不冲突。运行时按固定顺序注入全部启用规则，规则不能覆盖固定事实；冲突不导致场次暂停或失败。
- **D7 报告最低内容：** V3.5 主动退出（含刷新、关闭、离开）只有在服务端确认至少一个完整轮时才生成报告；完整轮包含双方正式消息、分析与风险、必要呈现确认、计分及实际资金动作保存。仅开场、未确认草稿或没有完整轮的半轮不生成报告、不开放报告重试，显示“未形成可复盘内容”；已有完整轮后在后续半轮退出仍生成报告，如实保留未完成内容。退出不判胜负，`winner/finalTrustScore` 为空。旧会话沿用当时规则。
- **D8 同主题反证升级：** 同一 `subject_key` 的反证允许由 PARTIAL 升级为 CONFIRMED 一次，必须有新的可靠确认依据并使用新的 `progress_key`；以冻结的“人物＋场景”初始分减20（下限0）为目标，只降不升。同档重复、旧请求重试和降档不重复扣分；升级不解除该主题或其他主题的限制。
- **D9 解说三栏卡（本次新增确认）：** 按下方参考图组织“轮次与阶段＋骗子的手段→骗子想做什么？＋真实受骗倾向变化”。需求方已明确选择展示真实分数及变化，覆盖旧版“过程分不进入解说或实时SSE”的限制；截图中的“+12、50→62”和人物姓名只作样例，不固定使用。保留独立风险节点条；角色不可见数值，计分、付款门槛和胜负规则不因展示调整。**解说与复盘分字段保存：** 保留原 `speechAnalysis`/`methodAnalysis` 作为复盘报告使用的完整分析；新增 `methodShort`（2～12字手段标签）和 `intentShort`（12～40字意图句）只供实时三栏解说。两组字段同轮保存，报告/历史继续读完整字段，不用短文本覆盖原分析。具体接口、提示词、样式与验收见 Task 5A。
