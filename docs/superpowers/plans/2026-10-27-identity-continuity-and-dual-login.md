# Identity continuity and dual login implementation plan

**Goal:** 修复冒充身份姓名、首次付款后无理由停止，以及同浏览器用户与管理员登录互相覆盖。

**Architecture:** 复用冻结画像与既有提示词版本迁移，补充明确的亲属姓氏事实并约束自然态度连续性。服务端在同一安全 Cookie 会话中分别保存 USER/ADMIN 的认证上下文和 CSRF，前端标签页记住所使用的身份；权限仍由服务端账号角色决定。

**Tech Stack:** Spring Boot / Spring Security / Vue / Vitest / JUnit。

**Spec:** 本次用户提供的三项问题与截图。

## Constraints and review focus

- 不重写旧提示词迁移校验和，不修改历史演绎。
- 无已知家庭姓氏时不得编造；已明确的父子姓氏冲突可构成反证。
- 暂缓追加不等于永久停止，资金事实和损失必须保留。
- 用户不能获得管理权限；两种身份的登录、退出和 CSRF 更新不能互相清除。
- 保留会话固定攻击防护和同账号并发登录限制。
