# 投资场景话术串用修复

日期：2026-10-25。

## 现象与原因

用户截图显示“虚假投资诈骗”第8轮，骗子却说“第一单不用您垫钱，做完直接发8块报酬”，并发送“体验任务操作步骤”，受害者随之讨论做任务的步骤。这是场景推进串用：投资应围绕项目、出资、收益及提现，而不是按完成订单/任务支付佣金。单独一个小金额不作为场景错误或非法资金的判据。

检查发现V23新增的通用SCAMMER版本5确实包含“首单报酬8元，不用垫钱，您先试一单看看”的刷单案例，三个场景都会看到；此前为了修复报酬承诺误入账，错误地把具体刷单话术放到了共用模板中。该文本是明确的跨场景污染源，但没有读取这次供应商完整输入/输出，不能断言模型内部只受这一因素影响。

原场景推进方向虽各不相同，但只提供正向目标，缺乏防止不同场景流程串用的约束；通用action示例也使用“任务链接”。

## 最小修改

- 新增prompts/v7/scammer.txt，移除固定8元、首单免垫付的示例；改为不含特定场景与金额的“承诺不入账、实际执行才入账”说明。通用action示例改成相关说明材料。
- ScenarioGoalRules.scammerHint分别补充场景边界：刷单以任务、垫付、佣金推进；投资围绕项目、出资、收益、提现，不能转为做任务拿佣金，也不能在没有出资时虚构已产生投资收益；借款保持亲友身份与借款语境。
- 明确资金规则允许REWARD，不代表每个场景必须发报酬；投资体验不能直接套刷单流程。不新增最低金额、强制金额或禁用REWARD规则，不修改既有资金口径与累计上限。
- 新增V24迁移激活SCAMMER版本6；V1～V23和已发布模板原样保留，旧会话原模板ID不迁移。迁移集成检查的最终版本断言同步为24。
- README当前迁移范围同步为V1～V24。没有修改前端场景标签，也不通过改标签掩盖话术问题。

## 简单验证与使用

仅运行ScammerScenarioPromptTest，覆盖三个场景实际AgentRunner提示词渲染：不含共用8元/首单示例、保留各场景推进方向和边界、承诺不入账说明仍在、无遗漏占位符。结果见backend/target/scammer-scenario-prompt-test.log及对应Surefire报告。

按Ponytail控制范围，没有调用真实模型，没有连接或迁移业务数据库，也没有跑全量测试或浏览器验证；此次未单独执行V24实库迁移，使用已有Java迁移模式并完成编译。

需重启后端，让Flyway按应用既有流程应用V24，再开始新场次使用新模板。旧场次沿用冻结模板及已有对话，不会自动重写历史；此前已串成任务的话术可能继续影响该旧场次，建议重新开始。此修改验证了输入的场景隔离，不等同于真实模型输出已全面验收。
