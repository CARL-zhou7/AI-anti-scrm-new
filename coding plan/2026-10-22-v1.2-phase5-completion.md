# V1.2 第五阶段完成记录（2026-10-22）

按照最新开发计划完成报告 v2 和旧报告 v1 兼容。报告仍由原有持久化任务队列生成；第六阶段未开始，等待用户确认。

## 本次修改

- 追加 V12：报告结构版本默认 2，CHECK 仅允许 1/2；原有报告行及内容不重写。V13 启用 REPORT Prompt v2，保留旧 Prompt。
- 新会话按启用的 REPORT Prompt 版本固定 runtime 的 report_content_schema_version；正式结束创建报告行及缺失报告修复都使用该冻结值，缺省为 1。不会因数据库默认值或当前启用 Prompt 改变旧会话报告结构。
- 使用共同的报告内容接口表示 v1/v2，JSON 保留具体字段；ReportView 和内容均明确带 contentSchemaVersion。没有可展示内容时顶层版本为 null。旧无版本字段的存储 JSON 仍按 v1 解析。
- 新报告包括一句话结果与依据、四段总结、最多三个关键节点、两至三条建议和三个资金总额。严格校验 JSON 字段、重复键、尾随内容和整数类型；总结 300—800 字，校验节点轮号及可选原话引用，拒绝结果名称或资金摘要不一致。
- 资金上下文只取冻结人物/已保存过程/正式结果和入账流水；生成前核对支付、实际返款及净亏损与会话摘要一致，模型输出必须与其一致。声称返款和预留释放不作为实际返款/亏损。
- 报告执行器沿用原有超时、失败、任务令牌及条件写入机制；按报告行版本选择解析与校验。重试保留原行版本及固定 Prompt。脚本客户端使用真实任务尝试号，以便验证首次失败、再次成功的恢复路径。
- 前端按版本展示：v2 四段总结、关键节点、建议、资金摘要，v1 继续显示原五部分；失败重试和提前终止无报告分支沿用。没有改风险图、实时演绎或语音。
