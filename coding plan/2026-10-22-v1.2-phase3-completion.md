# V1.2 第三阶段完成记录（2026-10-22）

本次依据更新后的四份设计文档、OpenAPI 与开发计划，修订阶段 1/2，并完成阶段 3。阶段 4 尚未开始，等待用户确认。

## 修改内容

- 核对 V7 基础事实及三套场景种子，与更新后的 PRD 一致，无需重写旧迁移。历史人物详情按冻结的当前场景展示；Agent 读取选定场景，Scammer 只获得公开背景，不获得余额、预留或内部心理。
- V8 已执行，因此保持原文件及校验和；在新增 V9 中补充 related_payment_id、索引、外键和返款关联 CHECK，再启用三类 Prompt v2。V10～V13 编号不变，旧会话固定的 Prompt、快照和报告不变。
- 新会话固定 funds-v2。Victim 仅付款/释放预留，Scammer 仅实际返款；claimedRefundYuan 为临时内部字段，不写流水、不公开。刷单/投资累计返款不超过 300、累计支付及关联原付款剩余可返额；借款拒绝结构化返款及声称金额。
- 金额必须为正整数；付款不得透支；预留释放有理由且不超过冻结总额；首笔不计追加。拒绝重复动作、旧轮付款复述、没有实际执行依据的动作。非法输出进入原有有限重生预算，错误台词不保存或发布。
- 消息、流水、轮次和会话摘要在同一事务落库；重复回执不重复入账。资金提交后才进行正式 Narrator 分析，前四轮候选预检仍保留。数据库失败时整笔回滚。
- 新轮次继承累计亏损/追加次数；状态、历史及模型资金上下文读取使用一致性快照，避免并发入账时混合读取新旧数据。历史 API 输出有序流水，不暴露内部返款关联 ID。
- 维持旧结果码、报告 v1、PRD-V3.2 阶段预览标记；没有实现阶段 4 的新结局与提前终止，也没有提前做阶段 6 的完整流水 UI。
